# 02 · 部署指南

> 本文描述 Snail-IoT 的两种部署方式：① Docker Compose 编排（第 1–9 节）；② Kubernetes（Docker Desktop 内置 k8s）+ Jenkins 自动化流水线（第 10–11 节）。
> 配套可视化图表见 [diagrams/02-部署拓扑图.html](file:///d:/DevProjects/snail/docs/diagrams/02-部署拓扑图.html)。

---

## 1. 部署架构总览

部署分为两层 Compose 编排：

| 编排文件 | 位置 | 职责 | 网络 |
| --- | --- | --- | --- |
| 根编排 | [docker-compose.yml](file:///d:/DevProjects/snail/docker-compose.yml) | 基础设施：PostgreSQL(pgvector) + Redis | 默认创建 `devprojects_default` |
| 业务编排 | [iot-platform/script/docker/docker-compose.yml](file:///d:/DevProjects/snail/iot-platform/script/docker/docker-compose.yml) | 业务与中间件：Nacos/ES/Kafka/EMQX/MinIO/后端/SBA/SnailJob/SnailAI/前端 | 复用外部网络 `devprojects_default` |

**为什么分两层**：基础设施（数据库、缓存）生命周期长、数据需持久化；业务容器迭代频繁。分层后业务容器可独立重建而不影响数据。业务编排通过 `external: true` 复用根编排创建的网络，从而让所有容器以服务名互访。

1. **JDK 21** + **Maven 3.9+**（构建后端）
2. **Node.js ≥ 20.19** + **pnpm ≥ 10**（构建前端，或使用容器内多阶段构建）

## 4. 部署步骤

### 步骤 1：启动基础设施

```bash
cd d:/DevProjects/snail
docker compose -f docker-compose.yml up -d
```

此步创建 `devprojects_default` 网络，并启动 `ruoyi-postgres`、`ruoyi-redis`。`init-vector.sql` 会在首次初始化数据库时执行（创建 pgvector 扩展等）。

验证：

```bash
docker ps --filter name=ruoyi-postgres --filter name=ruoyi-redis
```

### 步骤 2：构建并安装框架底座

产品 `iot-platform` 继承 `org.dromara:iot-vue-plus:6.0.0` 作为父 POM，**必须先将框架安装到本地 Maven 仓库**：

```bash
cd d:/DevProjects/snail/thirdparty/iot-vue-plus
mvn -DskipTests clean install
```

### 步骤 3：构建产品后端

```bash
cd d:/DevProjects/snail/iot-platform
mvn -Pprod -DskipTests clean package
```

产出：`iot-platform-admin/target/iot-platform-admin.jar`。

> `-Pprod` 激活生产打包；`iot-server` 容器以 `SPRING_PROFILES_ACTIVE=prod` 运行。

### 步骤 4：启动业务编排

```bash
cd d:/DevProjects/snail/iot-platform
docker compose -f script/docker/docker-compose.yml up -d --build
```

首次构建会编译以下镜像：

| 镜像 | 构建上下文 |
| --- | --- |
| `iot-platform/iot-platform-admin:1.0.0` | `iot-platform-admin` |
| `iot-platform/monitor-admin:6.0.0` | `thirdparty/iot-vue-plus/iot-extend/iot-monitor-admin` |
| `iot-platform/snailjob-server:2.0.2` | `thirdparty/iot-vue-plus/iot-extend/iot-snailjob-server` |
| `iot-platform/snailai-server:1.1.1` | `thirdparty/iot-vue-plus/iot-extend/iot-snailai-server` |
| `iot-platform/plus-ui:1.0.0` | `plus-ui` |

### 步骤 5：验证

```bash
docker compose -f script/docker/docker-compose.yml ps
```

访问 **http://localhost** → 出现登录页 → `admin / admin123` 登录成功即部署完成。

## 5. 启动顺序与依赖

```
postgres / redis (根编排)
        │
        ▼
nacos ─ elasticsearch ─ kafka ─ emqx ─ minio ─ minio-init
        │(healthcheck)
        ▼
   iot-server ──depends_on──▶ elasticsearch(healthy), kafka(healthy)
        │
        ├─▶ iot-sba ──▶ iot-snailjob
        │           └─▶ iot-snailai
        ▼
     iot-web (depends_on: iot-server, iot-sba, iot-snailjob, iot-snailai)
```

**关键依赖**：`iot-server` 等待 `elasticsearch` 与 `kafka` 健康后才启动；`iot-snailjob` / `iot-snailai` 依赖 `iot-sba` 完成注册。

## 7. 日常运维命令

```bash
# 启动全部（含重建镜像）
docker compose -f script/docker/docker-compose.yml up -d --build

# 停止（保留数据卷）
docker compose -f script/docker/docker-compose.yml down

# 停止并删除数据卷（谨慎）
docker compose -f script/docker/docker-compose.yml down -v

# 查看某服务日志
docker compose -f script/docker/docker-compose.yml logs -f iot-server
```

```bash
cd iot-platform

docker compose -f script/docker/docker-compose.yml build iot-server
docker compose -f script/docker/docker-compose.yml up -d iot-server
```

**前端改动后重新部署**：

```bash
docker compose -f script/docker/docker-compose.yml build iot-web
docker compose -f script/docker/docker-compose.yml up -d iot-web
```

## 8. 故障排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| `iot-nacos` unhealthy | Nacos 冷启动慢（Spring 上下文约 90s，整体约 3 分钟） | 编排已配 `start_period: 180s`，耐心等待；必要时 `docker logs iot-nacos` |
| `iot-kafka` unhealthy | KRaft 格式化/选主耗时 | 已配 `start_period: 30s`；检查 `docker logs iot-kafka` |
| `iot-emqx` unhealthy | `emqx ctl status` 探测失败或启动中 | 等待并重试；确认 1883/18083 未被占用 |
| 后端连不上 Redis | 密码不匹配 | 确认 `ruoyi-redis` 以 `--requirepass 123456` 启动，且 `REDIS_PASSWORD=123456` |
| 后端连不上 Nacos | 默认未启用 Nacos（`NACOS_ENABLED:false`） | 本部署默认不启用；如需启用见下方说明 |
| 前端 200 但接口 404 | 后端未就绪或反代路径错误 | 检查 `iot-server` 状态与 Nginx `/prod-api` 反代 |
| `no space left` | ES/Kafka 数据卷占用过多 | `docker system prune`、清理数据卷 |

### 关于 Nacos

业务编排启动了 `iot-nacos`（鉴权开启，`nacos/123456`），但后端**默认不接入**（`NACOS_ENABLED:false`）。原因：Spring Cloud Alibaba 2025.1.0.0 官方适配 Spring Boot 4.0，而框架使用 Spring Boot 4.1.0，存在版本错位风险。产品 POM 将 Nacos 依赖置于独立 `profile`，默认不激活；需要接入时：

```bash
mvn -Pnacos -DskipTests clean package
```

并设置 `NACOS_ENABLED=true` 及对应 `NACOS_USERNAME` / `NACOS_PASSWORD`。

## 10. Kubernetes 部署（Docker Desktop 内置 k8s）

除 Compose 外，整套服务也可部署到 **Docker Desktop 内置的 Kubernetes**。该集群与 Docker 引擎共享镜像存储，因此本地 `docker build` 产出的镜像可被集群直接使用（`imagePullPolicy: IfNotPresent`），**无需私有镜像仓库**。

同一集群内支持 **多环境并存**：每个环境一个独立命名空间，前端入口使用互不冲突的 NodePort（`dev` → 30080、`prod` → 30081），可同时运行、互不干扰。

### 10.1 前置条件

1. **Docker Desktop → Settings → Kubernetes → Enable Kubernetes**（勾选后应用并等待状态变为 running）
2. `kubectl config get-contexts` 能看到 `docker-desktop` 上下文
3. 业务镜像已构建（可由第 12 节 GitHub Actions 流水线自动完成，或参考 `script/docker/docker-compose.yml` 手动 `docker build`）：
   `iot-platform/iot-platform-admin:1.0.0`、`iot-platform/monitor-admin:6.0.0`、`iot-platform/snailjob-server:2.0.2`、`iot-platform/snailai-server:1.1.1`、`iot-platform/plus-ui:1.0.0`

> **端口占用**：k8s 的 `iot-web` 使用 NodePort（dev 30080 / prod 30081），**不再占用宿主 80 端口**，因此可与 Compose 栈共存；若 Compose 栈占用了 30080/30081，请调整或先停掉。

### 10.2 清单目录结构

```
iot-platform/script/k8s/
├── namespace.yaml              # 命名空间（部署时按环境渲染为 iot-platform-<env>）
├── secret.yaml                 # 数据库/Redis/MinIO 凭据（Opaque）
├── infrastructure/             # 中间件：postgres / redis / elasticsearch / kafka / emqx / minio
├── apps/                       # 应用：iot-server / iot-sba / iot-snailjob / iot-snailai / iot-web
├── db-init-job.yaml            # 数据库初始化 Job（按序执行全部 SQL）
├── db-init.sh                  # 生成 SQL ConfigMap + 重建并等待 Job
├── deploy.sh                   # 一键部署（接受 dev|prod 参数，含顺序与就绪等待）
└── destroy.sh                  # 卸载（删除目标环境命名空间，数据一并删除）
```

> 清单中的命名空间硬编码为 `iot-platform`，`deploy.sh` / `db-init.sh` 在部署时会**渲染到临时目录**并替换为目标环境命名空间，同时把 `iot-web` 的 `LoadBalancer:80` 改写为对应 NodePort。仓库内清单保持可读、不随环境变化。

### 10.3 一键部署

```bash
cd d:/DevProjects/snail
bash iot-platform/script/k8s/deploy.sh dev     # 开发环境（默认，命名空间 iot-platform-dev）
bash iot-platform/script/k8s/deploy.sh prod    # 生产环境（命名空间 iot-platform-prod）
```

脚本按依赖顺序执行：

```
namespace → secret → infrastructure(apply)
          → 等待 postgres / redis rollout
          → db-init.sh（ConfigMap 生成 → Job → wait complete）
          → apps(apply)
          → 逐个等待 deployment rollout（server / sba / snailjob / snailai / web）
```

### 10.5 代码更新后的构建发布（多项目）

k8s 中的镜像不会随源码变化自动更新，改完代码需**重新编译 → 重建镜像 → 重启 Deployment**。页面上的「发布部署」只负责更新镜像/重启实例，不执行编译。

平台采用「**一个通用 Jenkins 流水线 + 每个应用登记构建配置**」：新增项目只要在「应用管理」里填好配置，无需在 Jenkins 中新建 Job。

#### 1. 添加项目（应用管理 → 新增）

| 字段 | 说明 | 示例（iot-server） |
| --- | --- | --- |
| 应用编码 | 唯一标识 | `iot-server` |
| 仓库地址 | Git 地址，或 Jenkins 容器内本地路径 | `/workspace/snail` |
| 分支 | Git 分支 | `main` |
| 构建目录 | 相对代码根目录，命令在此执行 | `.` |
| 构建命令 | 留空则由 Dockerfile 内部完成构建 | `mvn -B -DskipTests -f thirdparty/iot-vue-plus/pom.xml clean install && mvn -B -Pprod -DskipTests -f iot-platform/pom.xml clean package` |
| Dockerfile | 相对代码根目录 | `iot-platform/iot-platform-admin/Dockerfile` |
| 镜像名称 | **不含 tag**，构建时用版本号作 tag | `iot-platform/iot-platform-admin` |
| 工作负载 / 容器 | 目标 Deployment / 容器名 | `iot-server` / `iot-server` |

- 仓库地址以 `/` 开头时直接使用 Jenkins 挂载的工作区（如 `/workspace/snail`），**本地未提交的改动同样生效**；填 Git 地址（如 `https://github.com/xxx/repo.git`）则每次构建浅克隆到 `/workspace/repos/{应用编码}`。
- 前端 `iot-web` 的构建命令留空，由 `plus-ui/Dockerfile` 多阶段构建完成 `pnpm install + build:prod`，避免重复构建。
- 依赖下载：Jenkins 挂载宿主 `~/.m2` 作为本地仓库复用缓存（已有依赖不重复下载），并通过 `script/jenkins/maven/settings.xml` 将 central 指向阿里云镜像加速；`build-app.sh` 以 `MAVEN_ARGS=-s ...` 自动注入，构建命令无需改动。
- JAR 下载：应用配置「JAR 路径」后（如 `iot-platform/iot-platform-admin/target/*.jar`），构建会将其归档到 Jenkins，任务列表中构建成功的记录会出现【下载 JAR】按钮。

#### 2. 触发构建（两个入口）

- 【自动化部署】→ 工具栏【构建应用】→ 选择应用、填写版本/Tag、选择目标环境 → 确定；
- 【自动化部署】→【应用管理】→ 每行【构建】按钮。

两种入口都会弹出日志抽屉，实时显示 Jenkins 控制台输出（排队中 → 构建中 → 成功/失败）。流水线阶段：准备代码 → 执行构建 → 归档 JAR → 构建镜像 → 部署到 Kubernetes，实际执行的是 [build-app.sh](file:///d:/DevProjects/snail/iot-platform/script/jenkins/build-app.sh)。

> 日志只在抽屉里实时查看，不落库、不持久化；关闭抽屉即停止轮询，历史日志可到 Jenkins 页面 `snail-app-build` 的构建记录查看。Jenkins 首次启动或修改 `casc/jenkins.yaml` 后需执行 `docker restart iot-jenkins`，再用 `POST /reload` 或重启使 Job 生效。

#### 方式二：本机手动构建

#### 后端（iot-server）

```powershell
# PowerShell 下 Maven 参数须放入 MAVEN_OPTS，否则 -Dmaven.repo.local 会被截断
$env:MAVEN_OPTS='-Duser.home=D:\DevProjects\snail\.build-home -Dmaven.repo.local=C:\Users\ThinkPad\.m2\repository'
mvn.cmd -f d:\DevProjects\snail\iot-platform\pom.xml -pl iot-platform-admin -am package -DskipTests

# 产物：iot-platform-admin/target/iot-platform-admin.jar（Dockerfile 中 ADD 的路径）
docker build -t iot-platform/iot-platform-admin:1.0.0 d:\DevProjects\snail\iot-platform\iot-platform-admin
kubectl -n iot-platform-dev rollout restart deployment/iot-server
kubectl -n iot-platform-dev rollout status deployment/iot-server
```

#### 前端（iot-web）

```powershell
docker build -t iot-platform/plus-ui:1.0.0 d:\DevProjects\snail\iot-platform\plus-ui
kubectl -n iot-platform-dev rollout restart deployment/iot-web
kubectl -n iot-platform-dev rollout status deployment/iot-web
```

> 前端 Dockerfile 为多阶段构建，容器内已完成 `pnpm install` + `pnpm run build:prod`，无需在本机装 Node。

#### 前后端都改

两段按任意顺序依次执行即可。镜像 tag 复用 `:1.0.0` 时依赖 `imagePullPolicy: IfNotPresent` 使用本地镜像；若改为拉取远端仓库，需递增 tag（如 `1.0.1`）并同步修改 Deployment 与 `iot_deploy_app.artifact`。

#### 其他变更

- **SQL 变更**（菜单、权限、表结构）不会自动执行，需手动导入：

  ```powershell
  kubectl -n iot-platform-dev exec -i deploy/iot-postgres -- psql -U postgres -d ruoyi -c "<SQL>"
  ```

- **验证**：`kubectl -n iot-platform-dev get pods` 确认新 Pod `Running`，`kubectl -n iot-platform-dev logs deploy/iot-server --tail=50` 看到 `Started IotApplication` 即启动成功。

### 10.6 卸载

```bash
bash iot-platform/script/k8s/destroy.sh dev     # 卸载开发环境
bash iot-platform/script/k8s/destroy.sh prod    # 卸载生产环境
```

> 该命令删除目标环境命名空间，默认 StorageClass 回收策略为 `Delete`，**PVC 数据会一并删除**。

### 10.7 与 Compose 的差异

| 维度 | Compose | Kubernetes |
| --- | --- | --- |
| 服务发现 | 服务名（`devprojects_default` 网络） | Service DNS（同上服务名） |
| 数据库初始化 | 容器首启执行 `init-vector.sql`，业务 SQL 手动导入 | `iot-db-init` Job 按固定顺序执行全部 SQL（幂等，`sys_user` 存在即跳过） |
| 前置依赖等待 | `depends_on` + `healthcheck` | `initContainer`（`iot-web` 等待 4 个后端）+ `readinessProbe` |
| 对外入口 | `ports: 80` | 各环境独立 `Service type=NodePort`（dev 30080 / prod 30081） |

## 11. Jenkins 自动化构建部署

Jenkins 以容器方式运行，内置 JDK21 / Maven / Node22+pnpm / Docker CLI / kubectl，串联「构建后端 → 构建前端 → 构建镜像 → 部署到 k8s → 冒烟验证」全流程。

### 11.1 启动 Jenkins

```bash
cd d:/DevProjects/snail
docker compose -f iot-platform/script/jenkins/docker-compose.yml up -d --build
```

首次构建会安装 Maven / Node / Docker CLI / kubectl 与全部插件，耗时较长。

| 项 | 值 |
| --- | --- |
| 访问地址 | http://localhost:8090/ |
| 默认账号 | `admin / admin123` |
| 配置方式 | JCasC（[casc/jenkins.yaml](file:///d:/DevProjects/snail/iot-platform/script/jenkins/casc/jenkins.yaml)） |

容器挂载：

| 宿主 | 容器 | 用途 |
| --- | --- | --- |
| `../../../`（仓库根） | `/workspace/snail` | Job 通过 `file:///workspace/snail` 本地克隆 |
| `/var/run/docker.sock` | `/var/run/docker.sock` | 复用宿主引擎构建镜像 |
| `%USERPROFILE%\.kube` | `/root/.kube`（只读） | kubectl 凭据 |
| `./casc` | `/var/jenkins_home/casc_configs` | JCasC 配置 |

> 容器以 `root` 运行以访问 `docker.sock`；`extra_hosts` 将 `kubernetes.docker.internal` 指向宿主，供容器内访问 k8s API。

### 11.2 预置内容

JCasC 首次启动即完成：
- 关闭安装向导，创建管理员 `admin/admin123`；
- 创建流水线 Job **`snail-iot-cicd`**，SCM 指向 `file:///workspace/snail`（分支 `main`），脚本路径 `iot-platform/Jenkinsfile`。

### 11.3 流水线阶段

| 阶段 | 动作 |
| --- | --- |
| 拉取代码 | 从 `/workspace/snail` 克隆到工作区（`ALLOW_LOCAL_CHECKOUT`） |
| 构建后端 | `mvn -DskipTests clean install`（`thirdparty/iot-vue-plus`）→ `mvn -Pprod -DskipTests clean package`（`iot-platform`） |
| 构建前端 | `pnpm install --frozen-lockfile` + `pnpm run build:prod` |
| 构建镜像 | `docker build` 出 5 个业务镜像 |
| 部署到 Kubernetes | 规整 kubeconfig 后执行 `script/k8s/deploy.sh dev`（部署到 `iot-platform-dev`） |
| 冒烟验证 | 校验 `iot-web` 页面可访问，且 4 个后端服务 DNS/端口连通 |

### 11.4 触发构建

打开 http://localhost:8090/ → 进入 **`snail-iot-cicd`** → **Build Now**。

### 11.5 注意事项

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Permission denied` 操作 docker.sock | 宿主 socket 属组与容器用户不匹配 | 编排已设 `user: root` |
| kubectl 连接 `127.0.0.1:6443` 超时 | 容器内 `127.0.0.1` 指向容器自身 | 流水线已将 server 改写为 `kubernetes.docker.internal:6443` |
| `dubious ownership` 报错 | bind-mount 仓库属主不一致 | 镜像内已 `git config --system --add safe.directory '*'` |
| `Non-resolvable parent POM` | 未先安装框架底座 | 流水线已内置 `thirdparty/iot-vue-plus` 的 `install` 步骤 |
| k8s 部署通不过 | 命名空间/端口被占 | 该流水线固定部署 `dev`（`iot-platform-dev`，NodePort 30080），确认该环境未被占用 |

## 12. GitHub Actions 自动化部署（推荐）

> 本节对应「代码提交后一键部署和发布」的目标，是第 11 节 Jenkins 方案的**替代/并行**选择。两者都可运行，互不影响（都通过 `script/k8s/deploy.sh <env>` 部署）。

### 12.1 方案概览

| 环境 | 命名空间 | 前端入口 | 触发方式 | 工作流 |
| --- | --- | --- | --- | --- |
| dev（开发） | `iot-platform-dev` | http://localhost:30080/ | **推送 `main` 分支自动部署** + 手动 | [deploy-dev.yml](file:///d:/DevProjects/snail/.github/workflows/deploy-dev.yml) |
| prod（生产） | `iot-platform-prod` | http://localhost:30081/ | 仅**手动 Run workflow**（可填发布版本号） | [release-prod.yml](file:///d:/DevProjects/snail/.github/workflows/release-prod.yml) |

代码来源：本仓库 `https://github.com/ksf127/Snail-IoT.git`（公开仓库，`actions/checkout` 无需额外凭据）。

流水线阶段（与 Jenkins 一致）：

```
拉取代码 → 构建后端(thirdparty → iot-platform) → 构建前端(plus-ui)
        → 构建 5 个镜像 → deploy.sh <env> 部署到 k8s → 冒烟验证
```

### 12.2 前置条件：搭建 self-hosted runner

因为部署目标是**本机 Docker Desktop Kubernetes**，云端 runner 无法访问，需在**本机**注册一个 GitHub self-hosted runner。

1. 打开 `https://github.com/ksf127/Snail-IoT` → **Settings → Actions → Runners → New self-hosted runner**，选择 **Windows**，按页面提示执行 `config.cmd`。
2. **配置自定义标签 `snail-iot`**（工作流用 `runs-on: [self-hosted, snail-iot]` 匹配）：
   ```powershell
   ./config.cmd --url https://github.com/ksf127/Snail-IoT --token <页面给出的 token> --labels snail-iot
   ./run.cmd      # 前台运行；或用 ./svc.sh install 注册为服务常驻
   ```
3. runner 所在机器需具备：
   - **Git for Windows**（工作流用 `shell: bash`，依赖 Git Bash）
   - **JDK 21** + **Maven 3.9+**
   - **Node 22** + **pnpm 10**
   - **Docker Desktop**（已启用 Kubernetes）+ **kubectl**（指向 `docker-desktop` 上下文）

> 若希望 runner 用 WSL/Linux 环境，请改为 `runs-on: [self-hosted, snail-iot, linux]` 并确保路径与脚本兼容。

### 12.3 触发方式

**开发环境（自动）**：向 `main` 分支推送涉及 `iot-platform/**`、`thirdparty/**` 或 `init-vector.sql` 的提交，即自动构建并部署 dev。

**开发环境（手动）**：Actions → **部署开发环境** → **Run workflow**。

**生产环境（手动）**：Actions → **发布生产环境** → **Run workflow**（可填发布版本号）→ 构建并部署 prod。

### 12.4 发布登记（平台内可查）

`iot_deploy_app` / `iot_deploy_env` 两张登记表已内置本项目与 dev/prod 两个环境（见 `iot-platform/script/sql/postgres/iot_deploy.sql`），前端「自动化部署」页面的**发布弹窗**中的应用编码 / 目标环境下拉即读取该数据；如需新增应用或环境，直接维护这两张表即可。

### 12.5 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 工作流一直 `Waiting for a runner` | 无匹配 `snail-iot` 标签的在线 runner | 确认 runner 已启动且标签正确 |
| `bash: command not found` | 未安装 Git for Windows | 安装后重试（工作流指定 `shell: bash`） |
| `mvn: command not found` / `pnpm: not found` | runner 环境缺工具 | 按 12.2 安装 JDK21 / Maven / Node22 / pnpm |
| `kubectl` 连不上集群 | 未启用 Kubernetes 或上下文非 `docker-desktop` | Docker Desktop → Settings → Kubernetes 勾选启用 |
| prod 部署未执行 | prod 为手动触发 | 到 Actions 页面手动 Run workflow |
