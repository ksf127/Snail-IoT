# 02 · 部署指南

> 本文描述 Snail-IoT 的容器化部署方式：基础设施编排、业务编排、启动顺序与故障排查。
> 配套可视化图表见 [diagrams/02-部署拓扑图.html](file:///d:/DevProjects/snail/docs/diagrams/02-部署拓扑图.html)。

---

## 1. 部署架构总览

部署分为两层 Compose 编排：

| 编排文件 | 位置 | 职责 | 网络 |
| --- | --- | --- | --- |
| 根编排 | [docker-compose.yml](file:///d:/DevProjects/snail/docker-compose.yml) | 基础设施：PostgreSQL(pgvector) + Redis | 默认创建 `devprojects_default` |
| 业务编排 | [iot-platform/script/docker/docker-compose.yml](file:///d:/DevProjects/snail/iot-platform/script/docker/docker-compose.yml) | 业务与中间件：Nacos/ES/Kafka/EMQX/MinIO/后端/SBA/SnailJob/SnailAI/前端 | 复用外部网络 `devprojects_default` |

**为什么分两层**：基础设施（数据库、缓存）生命周期长、数据需持久化；业务容器迭代频繁。分层后业务容器可独立重建而不影响数据。业务编排通过 `external: true` 复用根编排创建的网络，从而让所有容器以服务名互访。

## 3. 前置条件

1. **JDK 21** + **Maven 3.9+**（构建后端）
2. **Node.js ≥ 20.19** + **pnpm ≥ 10**（构建前端，或使用容器内多阶段构建）
3. **Docker Desktop**（含 Compose v2）
4. 磁盘空间 ≥ 10 GB（镜像 + ES/Kafka 卷）

## 4. 部署步骤

### 步骤 1：启动基础设施

```bash
cd d:/DevProjects/snail
docker compose -f docker-compose.yml up -d
```

此步创建 `devprojects_default` 网络，并启动 `ruoyi-postgres`、`ruoyi-redis`。`init-vector.sql` 会在首次初始化数据库时执行（创建 pgvector 扩展等）。

验证：

```bash
docker ps --filter name=ruoyi-postgres --filter name=ruoyi-redis
```

### 步骤 2：构建并安装框架底座

产品 `iot-platform` 继承 `org.dromara:iot-vue-plus:6.0.0` 作为父 POM，**必须先将框架安装到本地 Maven 仓库**：

```bash
cd d:/DevProjects/snail/thirdparty/iot-vue-plus
mvn -DskipTests clean install
```

### 步骤 3：构建产品后端

```bash
cd d:/DevProjects/snail/iot-platform
mvn -Pprod -DskipTests clean package
```

产出：`iot-platform-admin/target/iot-platform-admin.jar`。

> `-Pprod` 激活生产打包；`iot-server` 容器以 `SPRING_PROFILES_ACTIVE=prod` 运行。

### 步骤 4：启动业务编排

```bash
cd d:/DevProjects/snail/iot-platform
docker compose -f script/docker/docker-compose.yml up -d --build
```

首次构建会编译以下镜像：

| 镜像 | 构建上下文 |
| --- | --- |
| `iot-platform/iot-platform-admin:1.0.0` | `iot-platform-admin` |
| `iot-platform/monitor-admin:6.0.0` | `thirdparty/iot-vue-plus/iot-extend/iot-monitor-admin` |
| `iot-platform/snailjob-server:2.0.2` | `thirdparty/iot-vue-plus/iot-extend/iot-snailjob-server` |
| `iot-platform/snailai-server:1.1.1` | `thirdparty/iot-vue-plus/iot-extend/iot-snailai-server` |
| `iot-platform/plus-ui:1.0.0` | `plus-ui` |

### 步骤 5：验证

```bash
docker compose -f script/docker/docker-compose.yml ps
```

访问 **http://localhost** → 出现登录页 → `admin / admin123` 登录成功即部署完成。

## 5. 启动顺序与依赖

```
postgres / redis (根编排)
        │
        ▼
nacos ─ elasticsearch ─ kafka ─ emqx ─ minio ─ minio-init
        │(healthcheck)
        ▼
   iot-server ──depends_on──▶ elasticsearch(healthy), kafka(healthy)
        │
        ├─▶ iot-sba ──▶ iot-snailjob
        │           └─▶ iot-snailai
        ▼
     iot-web (depends_on: iot-server, iot-sba, iot-snailjob, iot-snailai)
```

**关键依赖**：`iot-server` 等待 `elasticsearch` 与 `kafka` 健康后才启动；`iot-snailjob` / `iot-snailai` 依赖 `iot-sba` 完成注册。

## 6. 环境变量

`iot-server` 的 `application-prod.yml` 中所有连接均由环境变量注入，业务编排已预置：

| 变量 | 值 | 说明 |
| --- | --- | --- |
| `SPRING_PROFILES_ACTIVE` | `prod` | 激活生产配置 |
| `POSTGRES_HOST` | `ruoyi-postgres` | 复用根编排容器 |
| `POSTGRES_DB` / `POSTGRES_USERNAME` / `POSTGRES_PASSWORD` | `ruoyi` / `postgres` / `postgres` | 数据库 |
| `REDIS_HOST` / `REDIS_PASSWORD` | `ruoyi-redis` / `123456` | 缓存 |
| `ES_HOST` / `ES_PORT` / `EASY_ES_ENABLE` | `iot-elasticsearch` / `9200` / `true` | 搜索引擎 |
| `KAFKA_SERVERS` | `iot-kafka:9092` | 消息队列（容器内） |
| `MQTT_HOST` / `MQTT_PORT` / `MQTT_CLIENT_ENABLED` | `iot-emqx` / `1883` / `true` | MQTT |
| `SBA_HOST` / `SBA_PORT` | `iot-sba` / `9090` | 监控中心注册 |

## 7. 日常运维命令

```bash
# 启动全部（含重建镜像）
docker compose -f script/docker/docker-compose.yml up -d --build

# 停止（保留数据卷）
docker compose -f script/docker/docker-compose.yml down

# 停止并删除数据卷（谨慎）
docker compose -f script/docker/docker-compose.yml down -v

# 查看状态
docker compose -f script/docker/docker-compose.yml ps

# 查看某服务日志
docker compose -f script/docker/docker-compose.yml logs -f iot-server
```

**后端改动后重新部署**：

```bash
cd iot-platform
mvn -Pprod -DskipTests clean package
docker compose -f script/docker/docker-compose.yml build iot-server
docker compose -f script/docker/docker-compose.yml up -d iot-server
```

**前端改动后重新部署**：

```bash
docker compose -f script/docker/docker-compose.yml build iot-web
docker compose -f script/docker/docker-compose.yml up -d iot-web
```

## 8. 故障排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| `iot-nacos` unhealthy | Nacos 冷启动慢（Spring 上下文约 90s，整体约 3 分钟） | 编排已配 `start_period: 180s`，耐心等待；必要时 `docker logs iot-nacos` |
| `iot-kafka` unhealthy | KRaft 格式化/选主耗时 | 已配 `start_period: 30s`；检查 `docker logs iot-kafka` |
| `iot-emqx` unhealthy | `emqx ctl status` 探测失败或启动中 | 等待并重试；确认 1883/18083 未被占用 |
| 后端连不上 Redis | 密码不匹配 | 确认 `ruoyi-redis` 以 `--requirepass 123456` 启动，且 `REDIS_PASSWORD=123456` |
| 后端连不上 Nacos | 默认未启用 Nacos（`NACOS_ENABLED:false`） | 本部署默认不启用；如需启用见下方说明 |
| 前端 200 但接口 404 | 后端未就绪或反代路径错误 | 检查 `iot-server` 状态与 Nginx `/prod-api` 反代 |
| `no space left` | ES/Kafka 数据卷占用过多 | `docker system prune`、清理数据卷 |

### 关于 Nacos

业务编排启动了 `iot-nacos`（鉴权开启，`nacos/123456`），但后端**默认不接入**（`NACOS_ENABLED:false`）。原因：Spring Cloud Alibaba 2025.1.0.0 官方适配 Spring Boot 4.0，而框架使用 Spring Boot 4.1.0，存在版本错位风险。产品 POM 将 Nacos 依赖置于独立 `profile`，默认不激活；需要接入时：

```bash
mvn -Pnacos -DskipTests clean package
```

并设置 `NACOS_ENABLED=true` 及对应 `NACOS_USERNAME` / `NACOS_PASSWORD`。

## 9. 数据持久化

| 卷名 | 内容 |
| --- | --- |
| `pgdata`（根编排） | PostgreSQL 数据目录 |
| `iot-nacos-data` / `iot-nacos-logs` | Nacos 数据与日志 |
| `iot-es-data` | Elasticsearch 索引数据 |
| `iot-kafka-data` | Kafka 日志段 |
| `iot-emqx-data` / `iot-emqx-log` | EMQX 数据与日志 |
| `iot-minio-data` | MinIO 对象数据 |

> Redis 未挂载卷（缓存性质，可丢）。生产环境建议按需为 Redis 增加持久化卷。
