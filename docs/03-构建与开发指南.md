# 03 · 构建与开发指南

> 面向开发者的本地环境搭建、构建命令与常见问题。
> 前置：JDK 21、Maven 3.9+、Node ≥ 20.19、pnpm ≥ 10、Docker Desktop。

---

## 1. 工程依赖关系

```
thirdparty/iot-vue-plus   (框架底座，产出 iot-vue-plus:6.0.0 → 本地 Maven 仓库)
        ▲  <parent>
        │
iot-platform              (业务产品，继承父 POM)
   ├── iot-platform-common
   ├── iot-platform-modules (9 个业务模块)
   └── iot-platform-admin   (可执行 jar)
```

**关键**：产品 POM 中父 POM 的 `<relativePath/>` 为空，Maven 只能从本地/远程仓库解析 `org.dromara:iot-vue-plus:6.0.0`。因此**首次构建前必须先 `mvn install` 框架**，否则产品构建会报 `Non-resolvable parent POM`。

## 2. 后端开发

### 2.1 首次构建（顺序不可颠倒）

```bash
# ① 安装框架底座
cd d:/DevProjects/snail/thirdparty/iot-vue-plus
mvn -DskipTests clean install

# ② 构建产品
cd d:/DevProjects/snail/iot-platform
mvn -DskipTests clean package
```

### 2.2 日常构建命令

| 目的 | 命令 |
| --- | --- |
| 编译全部模块 | `mvn -DskipTests clean install` |
| 只打包后端 | `mvn -Pprod -DskipTests clean package` |
| 启用 Nacos profile | `mvn -Pnacos -DskipTests clean package` |
| 运行测试 | `mvn test` |
| 清理构建产物 | `mvn clean` |

> 构建产物：`iot-platform-admin/target/iot-platform-admin.jar`。

### 2.3 Windows 沙箱构建参数

若本机 Maven 因沙箱限制无法写入默认仓库/用户目录，需显式指定：

```powershell
mvn -Pprod -DskipTests clean package `
  "-Dmaven.repo.local=C:\Users\ThinkPad\.m2\repository" `
  "-Duser.home=D:\DevProjects\snail\.mvn-home"
```

`.mvn-home/` 为构建期用户目录，不应提交到版本库（见根 `.gitignore`）。

### 2.4 本地直接运行后端

依赖基础设施（PostgreSQL/Redis 等）已通过 Docker 启动。以 IDE 或命令行启动主类：

```
org.dromara.IotApplication   (iot-platform-admin)
```

启动后默认端口 `8080`，`spring.application.name=iot-platform`。

## 3. 前端开发

前端工程位于 [iot-platform/plus-ui](file:///d:/DevProjects/snail/iot-platform/plus-ui)，工程名 `iot-vue-plus`，版本 `6.0.0`。

### 3.1 安装依赖

```bash
cd d:/DevProjects/snail/iot-platform/plus-ui
pnpm install --registry=https://registry.npmmirror.com
```

### 3.2 开发与构建

| 目的 | 命令 |
| --- | --- |
| 启动开发服务器 | `pnpm dev` |
| 生产构建 | `pnpm build:prod` |
| 开发模式构建 | `pnpm build:dev` |
| 预览构建产物 | `pnpm preview` |
| 代码格式化 | `pnpm fmt` |
| 代码检查 | `pnpm lint` / `pnpm lint:fix` |

### 3.3 环境配置

| 文件 | 关键变量 | 说明 |
| --- | --- | --- |
| [.env.development](file:///d:/DevProjects/snail/iot-platform/plus-ui/.env.development) | `VITE_APP_BASE_API=/dev-api` | 开发环境接口前缀（Vite 代理到后端 8080） |
| [.env.production](file:///d:/DevProjects/snail/iot-platform/plus-ui/.env.production) | `VITE_APP_BASE_API=/prod-api` | 生产环境接口前缀（Nginx 反代） |

其他重要变量：

- `VITE_APP_ENCRYPT=true`：接口加解密开关（前后端须一致，RSA 公私钥成对配置）
- `VITE_APP_CLIENT_ID`：SSO 客户端 ID，与后端 `iot.sso.default-client-id` 一致
- `VITE_APP_MESSAGE_TRANSPORT=sse`：统一消息推送方式
- `VITE_APP_MONITOR_ADMIN` / `VITE_APP_SNAILJOB_ADMIN` / `VITE_APP_SNAILAI_ADMIN`：三大控制台地址

### 3.4 前端目录速览

```
plus-ui/src/
├── api/          # 接口定义（system/ 框架接口；device/collect/... 为 IoT 业务接口）
├── assets/       # 图标、图片、样式

└── views/        # 页面（device/product/app/dataset/group/archive/report/deploy/pay/...）
```

IoT 业务接口文件（`src/api/` 下）：`device.js`、`product.js`、`app.js`、`dataset.js`、`group.js`、`archive.js`、`report.js`、`deploy.js`、`pay.js`、`monitor.js`。

## 5. 常见问题（FAQ）

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| `Non-resolvable parent POM: org.dromara:iot-vue-plus:6.0.0` | 未安装框架 | 先执行 `thirdparty/iot-vue-plus` 的 `mvn clean install` |
| 构建写入 `D:\DevTools\maven` 失败 | Maven 默认仓库/用户目录受限 | 追加 `-Dmaven.repo.local` 与 `-Duser.home` |
| `mvn` 报找不到 `flatten` 插件 | 依赖下载不完整 | 重新执行构建；检查网络/镜像 |
| 前端 `pnpm install` 慢 | 默认源慢 | 使用 `--registry=https://registry.npmmirror.com` |
| `pnpm dev` 报端口占用 | `VITE_APP_PORT=80` 被占用 | 关闭占用 80 端口的进程，或改 `.env.development` |
| 接口 401/解密失败 | RSA 公私钥前后端不一致 | 确认 `.env` 与后端 `api-decrypt` 配置成对 |
| 登录验证码不显示 | Redis 未启动或密码不符 | 启动 `ruoyi-redis`，确认密码 `123456` |
| Nacos 相关类找不到 | 默认未激活 nacos profile | 使用 `mvn -Pnacos ...` |

## 6. 代码约定

- **Java 包名**：统一 `org.dromara.*`，业务产品位于 `org.dromara.iot.<module>`。
- **模块命名**：产品模块 `iot-platform-<name>`；框架模块 `iot-<name>`。
- **接口分组**：新增控制器所在包决定 SpringDoc 分组（`web/system/device/collect/monitor/sso/archive/report/deploy`）。
- **前端接口**：DTO 类型集中在对应 `types.ts`；页面组件位于 `src/views/<业务>/index.vue`。
- **提交前**：后端 `mvn -DskipTests clean install` 通过；前端 `pnpm lint` 通过。
