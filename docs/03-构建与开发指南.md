# 03 · 构建与开发指南

> 面向开发者的本地环境搭建、构建命令、Profile 切换与常见问题。
> 前置：JDK 21、Maven 3.9+、Node ≥ 20.19、pnpm ≥ 10、Docker Desktop（含 Compose v2）。

---

## 1. 工程依赖关系

```
thirdparty/iot-vue-plus   (框架底座，产出 org.dromara:iot-vue-plus:6.0.0 → 本地 Maven 仓库)
        ▲  <parent>
        │
iot-platform              (业务产品，继承父 POM)
   ├── iot-platform-common      # 常量与枚举
   ├── iot-platform-modules     # 12 个业务模块（device/permission/collect/...）
   └── iot-platform-admin       # 启动入口，产出可执行 jar
```

**关键**：产品 POM 中父 POM 的 `<relativePath/>` 为空，Maven 只能从本地/远程仓库解析 `org.dromara:iot-vue-plus:6.0.0`。因此**首次构建前必须先 `mvn install` 框架**，否则产品构建会报 `Non-resolvable parent POM`。

中间件与数据源（PostgreSQL / Redis / Kafka / EMQX / ES / MinIO / Nacos）由根目录 [docker-compose.yml](file:///d:/DevProjects/snail/docker-compose.yml) 与 [业务编排](file:///d:/DevProjects/snail/iot-platform/script/docker/docker-compose.yml) 提供，详见 [02 · 部署指南](file:///d:/DevProjects/snail/docs/02-部署指南.md)。

## 2. 后端开发

### 2.1 首次构建（顺序不可颠倒）

```bash
# ① 安装框架底座
cd d:/DevProjects/snail/thirdparty/iot-vue-plus
mvn -DskipTests clean install

# ② 构建产品
cd d:/DevProjects/snail/iot-platform
mvn -DskipTests clean package
```

构建产物：`iot-platform-admin/target/iot-platform-admin.jar`。

### 2.2 日常构建命令

| 目的 | 命令 |
| --- | --- |
| 编译并安装全部模块 | `mvn -DskipTests clean install` |
| 生产打包 | `mvn -Pprod -DskipTests clean package` |
| 本地 profile 打包 | `mvn -Plocal -DskipTests clean package` |
| 启用 Nacos 依赖/profile | `mvn -Pnacos -DskipTests clean package` |
| 运行测试 | `mvn test` |
| 清理构建产物 | `mvn clean` |

> 不显式指定时使用框架父 POM 的默认 profile `dev`（`activeByDefault`）。

### 2.3 Maven Profile 与生效方式

框架父 POM [pom.xml](file:///d:/DevProjects/snail/thirdparty/iot-vue-plus/pom.xml#L81-L120) 定义 `local` / `dev` / `prod` 三个 profile，核心属性是 `profiles.active`：

| Profile | `profiles.active` | `logging.level` | 是否默认 |
| --- | --- | --- | --- |
| `local` | `local` | `info` | 否 |
| `dev` | `dev` | `info` | 是 |
| `prod` | `prod` | `warn` | 否 |

打包时通过资源过滤写入 [application.yml](file:///d:/DevProjects/snail/iot-platform/iot-platform-admin/src/main/resources/application.yml#L63-L64)：

```yaml
spring:
  profiles:
    active: @profiles.active@
```

产品另有独立 `nacos` profile（仅追加 Nacos 依赖，默认不激活）。也可在启动时追加：`--spring.profiles.active=dev,nacos`。

### 2.4 Windows 沙箱构建参数

若本机 Maven 因沙箱限制无法写入默认仓库/用户目录，需显式指定：

```powershell
mvn -Pprod -DskipTests clean package `
  "-Dmaven.repo.local=C:\Users\ThinkPad\.m2\repository" `
  "-Duser.home=D:\DevProjects\snail\.mvn-home"
```

`.mvn-home/` 为构建期用户目录，不应提交到版本库（见根 `.gitignore`）。

### 2.5 本地直接运行后端

以 IDE 或命令行启动主类：

```
org.dromara.IotApplication   (iot-platform-admin)
```

启动后端口 `8080`，`spring.application.name=iot-platform`。本地运行默认使用 `dev` profile。

### 2.6 dev profile 的默认行为（易踩坑）

[application-dev.yml](file:///d:/DevProjects/snail/iot-platform/iot-platform-admin/src/main/resources/application-dev.yml) 与 prod 差异较大，本地启动前请确认：

| 项 | dev 默认 | 说明 |
| --- | --- | --- |
| 数据源 | `jdbc:postgresql://localhost:5432/ruoyi`，`postgres/postgres` | 硬编码，需本机可连通 |
| Redis | `localhost:6379`，**不配置密码** | 若容器开启了 `--requirepass`，需在 dev 中补 `password` |
| Spring Boot Admin | `enabled: false` | 本地不注册监控中心 |
| SnailJob | `enabled: false` | 不连接调度中心，本地调度器仍生效 |
| SnailAI | `enabled: true` | 连接 `127.0.0.1:18888`，`app-id: iot-vue-plus-001` |
| Ollama | `http://localhost:11434`，`qwen3:8b` / `nomic-embed-text` | 由 `thirdparty/snail-ai` 的 full compose 提供 |
| MyBatis-Plus SQL 日志 | `enabled: true`，输出到 console | 调试用，生产关闭 |
| ES / MQTT / Kafka | 默认关闭或按需开启 | 采集链路需显式开启对应客户端 |

> prod profile 下所有连接串均由环境变量注入（`POSTGRES_*`、`REDIS_*`、`ES_*`、`SBA_*` 等），且 `easy-es.enable`、`mqtt.client.enabled` 默认 `false`，详见 [02 · 部署指南 · 6.1](file:///d:/DevProjects/snail/docs/02-部署指南.md)。

### 3.3 环境配置

| 文件 | 关键变量 | 说明 |
| --- | --- | --- |
| [.env.development](file:///d:/DevProjects/snail/iot-platform/plus-ui/.env.development) | `VITE_APP_BASE_API=/dev-api` | 开发接口前缀，Vite 代理到 `http://localhost:8080` |
| [.env.production](file:///d:/DevProjects/snail/iot-platform/plus-ui/.env.production) | `VITE_APP_BASE_API=/prod-api` | 生产接口前缀，由 Nginx 反代到 `iot-server:8080` |

其他重要变量（两套环境均需一致）：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `VITE_APP_TITLE` / `VITE_APP_LOGO_TITLE` | `Snail-IoT` | 页面标题与 Logo 文案 |
| `VITE_APP_PORT` | `80` | 开发服务器端口（被占用时改这里） |
| `VITE_APP_ENCRYPT` | `true` | 接口加解密开关，须与后端 `api-decrypt` 一致 |
| `VITE_APP_RSA_PUBLIC_KEY` / `VITE_APP_RSA_PRIVATE_KEY` | 成对 RSA 密钥 | 与后端 `api-decrypt` 公私钥成对替换 |
| `VITE_APP_CLIENT_ID` | `e5cd7e4891bf95d1d19206ce24a7b32e` | 登录后写入 Token extra，请求需带同名 `clientid` 头 |
| `VITE_APP_MESSAGE_ENABLED` | `true` | 统一消息推送开关 |
| `VITE_APP_MESSAGE_TRANSPORT` | `sse` | `sse` / `websocket`，后端当前启用 SSE |
| `VITE_APP_MESSAGE_PATH` | `/resource/message` | 消息通道路径 |
| `VITE_APP_MONITOR_ADMIN` | dev 直连 9090 / prod `/admin/applications` | Spring Boot Admin 入口 |
| `VITE_APP_SNAILJOB_ADMIN` | dev 直连 8800 / prod `/snail-job` | SnailJob 控制台入口 |
| `VITE_APP_SNAILAI_ADMIN` | dev 直连 8900 / prod `/snail-ai` | SnailAI 控制台入口 |

> 登录鉴权链路（`CryptoFilter` → `/auth/login` → `clientid` 校验）见 [01 · 系统架构设计 · 5.1](file:///d:/DevProjects/snail/docs/01-系统架构设计.md)。

## 5. 常见问题（FAQ）

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| `Non-resolvable parent POM: org.dromara:iot-vue-plus:6.0.0` | 未安装框架 | 先执行 `thirdparty/iot-vue-plus` 的 `mvn clean install` |
| 构建写入 `D:\DevTools\maven` 失败 | Maven 默认仓库/用户目录受限 | 追加 `-Dmaven.repo.local` 与 `-Duser.home` |
| `mvn` 报找不到 `flatten` 插件 | 依赖下载不完整 | 重新执行构建；检查网络/镜像 |
| 启动报 Redis `NOAUTH Authentication required` | dev 未配置密码，但容器设置了 `requirepass` | 在 `application-dev.yml` 补 `spring.data.redis.password`，或用无密码 Redis |
| 启动连不上 PostgreSQL | dev 硬编码 `localhost:5432/ruoyi` | 启动 `docker compose -p devprojects up -d postgres` |
| 前端 `pnpm install` 慢 | 默认源慢 | 使用 `--registry=https://registry.npmmirror.com` |
| `pnpm dev` 报端口占用 | `VITE_APP_PORT=80` 被占用 | 关闭占用 80 端口的进程，或改 `.env.development` |
| 接口 401 /「客户端ID与Token不匹配」 | 请求未带 `clientid` 头，或与 `VITE_APP_CLIENT_ID` 不一致 | 确认前端 `clientid` 头与登录 Token 中的 `clientId` 一致 |
| 接口解密失败 | RSA 公私钥前后端不一致 | 确认 `.env` 与后端 `api-decrypt` 配置成对 |
| 登录验证码不显示 | Redis 未启动或密码不符 | 检查 Redis 连通性与 dev 密码配置 |
| Nacos 相关类找不到 | 默认未激活 nacos profile | 使用 `mvn -Pnacos ...` |
| 前端消息通道连不上 | 后端 `message.transport` 非 `sse`，或路径不一致 | 对齐 `VITE_APP_MESSAGE_TRANSPORT` / `VITE_APP_MESSAGE_PATH` |

## 6. 代码约定

- **Java 包名**：统一 `org.dromara.*`，业务产品位于 `org.dromara.iot.<module>`。
- **模块命名**：产品模块 `iot-platform-<name>`；框架模块 `iot-<name>`。
- **接口分组**：SpringDoc 按控制器所在包划分 13 个分组（`1.通用模块`…`13.任务调度模块`），配置位于 `springdoc.group-configs`；新增业务模块时在此追加对应分组。
- **前端接口**：DTO 类型集中在对应 `types.ts`；页面组件位于 `src/views/<业务>/index.vue`。
- **提交前**：后端 `mvn -DskipTests clean install` 通过；前端 `pnpm lint` 通过。
