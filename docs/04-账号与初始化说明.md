- 角色绑定见 `sys_user_role` / `sys_role` 种子数据（`test`、`test1` 各绑定一个演示角色）。

登录流程：

```
前端 login 页 ──▶ POST /auth/login（账号/密码/验证码/租户）
        │
        ├─ CryptoFilter：header `encrypt-key` 解密请求体（@ApiEncrypt）
        ├─ CaptchaController 校验验证码（Redis `global:captcha_codes:{uuid}`）
        ├─ IAuthStrategy（password / sms / email / social / xcx）校验身份
        └─ Sa-Token 签发 JWT（extra 写入 clientId）→ 前端保存
               后续请求：Authorization: Bearer <token> + clientid 头
```

> `clientid` 与 Token extra 中的 `clientId` 不一致会返回「客户端ID与Token不匹配」。前端取值来自 `VITE_APP_CLIENT_ID=e5cd7e4891bf95d1d19206ce24a7b32e`。

## 6. 初始化流程

### 6.1 Compose 环境：手动导入

1. 根编排首次启动 PostgreSQL 时，自动执行 [init-vector.sql](file:///d:/DevProjects/snail/init-vector.sql)（pgvector 扩展与向量表）。
2. 框架、业务与 AI 表需手动导入，**顺序不可颠倒**（业务表依赖框架 `sys_user` / `sys_menu`）：

```bash
# ① 框架基础表（PostgreSQL 方言）
thirdparty/iot-vue-plus/script/sql/postgres/postgres_iot_vue.sql
thirdparty/iot-vue-plus/script/sql/postgres/postgres_iot_workflow.sql
thirdparty/iot-vue-plus/script/sql/postgres/postgres_iot_job.sql
thirdparty/iot-vue-plus/script/sql/postgres/postgres_iot_ai.sql

# ② 产品业务表
iot-platform/script/sql/postgres/iot_platform.sql
iot-platform/script/sql/postgres/iot_permission.sql
iot-platform/script/sql/postgres/iot_sso.sql
iot-platform/script/sql/postgres/iot_pay.sql
iot-platform/script/sql/postgres/iot_ticket.sql
iot-platform/script/sql/postgres/iot_archive.sql
iot-platform/script/sql/postgres/iot_deploy.sql
iot-platform/script/sql/postgres/iot_cloud.sql
iot-platform/script/sql/postgres/iot_job.sql

# ③ SnailAI 表（PostgreSQL 方言）
thirdparty/snail-ai/script/sql/snail_ai_schema_pgsql.sql
```

示例（容器内执行）：

```bash
docker exec -i postgres psql -U postgres -d ruoyi < thirdparty/iot-vue-plus/script/sql/postgres/postgres_iot_vue.sql
```

> 不要使用 `script/sql/iot_vue.sql` 等不分方言的脚本；本项目为 PostgreSQL，请统一取 `postgres/` 目录下的版本。

### 6.2 K8s 环境：db-init Job 自动初始化

K8s 部署不手工导入，由 [db-init-job.yaml](file:///d:/DevProjects/snail/iot-platform/script/k8s/db-init-job.yaml) 配合 [db-init.sh](file:///d:/DevProjects/snail/iot-platform/script/k8s/db-init.sh) 完成：

| 机制 | 说明 |
| --- | --- |
| SQL 来源 | 4 个 ConfigMap：`iot-sql-vector` / `iot-sql-base` / `iot-sql-framework` / `iot-sql-iot` |
| 台账表 | `iot_schema_history(file_name TEXT PRIMARY KEY, applied_at TIMESTAMP DEFAULT now())` |
| 基础/框架脚本 | 仅在 `sys_user` 表不存在时执行一次（首次初始化） |
| 业务脚本 | 按文件名登记，每个脚本只执行一次，新增脚本自动增量执行 |
| 业务脚本顺序 | `iot_platform` → `iot_permission` → `iot_sso` → `iot_pay` → `iot_ticket` → `iot_archive` → `iot_deploy` → `iot_cloud` → `iot_job` |

> 新增业务 SQL 后，需同步更新 `db-init-job.yaml` 中的 ConfigMap，再重新执行 Job。完整部署步骤见 [02 · 部署指南 · 10.5](file:///d:/DevProjects/snail/docs/02-部署指南.md)。

### 6.3 已有数据库的同步更新

若数据库是**历史版本**（在「项目更名 / 昵称调整」之前初始化），种子脚本的改动不会回溯生效，需手动执行以下语句：

```sql
-- 1. 一级菜单更名：物联网平台 → Snail-IoT
UPDATE sys_menu
SET menu_name = 'Snail-IoT',
    remark    = 'Snail-IoT 目录'
WHERE menu_id = 1900000000000000001;

-- 2. 管理员昵称同步（替换历史昵称）
UPDATE sys_user
SET nick_name = '云澈'
WHERE user_name = 'admin';

-- 3. 一级菜单排序：Snail-IoT 由末尾调整到最前（order_num 50 → 0）
UPDATE sys_menu
SET order_num = 0
WHERE menu_id = 1900000000000000001;
```

> 全新初始化（直接执行 §6.1 / §6.2）无需执行本节。

#### 执行记录（2026-10-10）

已对本机历史库（库 `ruoyi`）执行上述同步：

```bash
docker exec postgres psql -U postgres -d ruoyi -c \
  "UPDATE sys_menu SET menu_name = 'Snail-IoT', remark = 'Snail-IoT 目录' WHERE menu_id = 1900000000000000001;"
docker exec postgres psql -U postgres -d ruoyi -c \
  "UPDATE sys_user SET nick_name = '云澈' WHERE user_name = 'admin';"
docker exec postgres psql -U postgres -d ruoyi -c \
  "UPDATE sys_menu SET order_num = 0 WHERE menu_id = 1900000000000000001;"
```

| 对象 | 更新前 | 更新后 |
| --- | --- | --- |
| `sys_menu`（1900000000000000001） | 物联网平台 / IoT 物联网平台目录 | Snail-IoT / Snail-IoT 目录 |
| `sys_user`（admin） | 云澈 | 云澈（原本已一致，无变更） |
| `sys_menu`（1900000000000000001）排序 | order_num = 50（末位） | order_num = 0（最前） |

## 7. 安全建议（生产）

1. **更换全部默认密码**：平台账号、PostgreSQL、Redis、Nacos、EMQX、MinIO、Spring Boot Admin / SnailJob / SnailAI / Jenkins。
2. **更换服务令牌**：SnailJob / SnailAI 的 token、`NACOS_AUTH_TOKEN`、`GITHUB_TOKEN`。
3. **更换 RSA 密钥对**：`api-decrypt` 的公私钥与前端 `.env` 中的 `VITE_APP_RSA_*` 成对替换。
4. **更换 JWT 密钥**：`sa-token.jwt-secret-key`（默认 `abcdefghijklmnopqrstuvwxyz`）。
5. **关闭匿名连接**：将 `EMQX_ALLOW_ANONYMOUS` 设为 `false` 并配置认证。
6. **关闭接口加密调试**：确保 `VITE_APP_ENCRYPT` 与后端 `api-decrypt.enabled` 状态一致。
7. **移除 Nginx 硬编码凭据**：`/jenkins-api/` 的 Basic 认证凭据应改为变量或独立认证。
8. **限制端口暴露**：仅对外暴露 80（或 443），其余中间件端口不应公开。
