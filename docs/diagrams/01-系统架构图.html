应用层

iot-platform-admin 是唯一启动入口，负责把所有业务模块装配进同一个 Spring Boot 进程（端口 8080，应用名 iot-platform）。

能力实现 / 配置关键点
登录鉴权Sa-Token 1.45.0 + JWTtoken-name: Authorization，is-concurrent: true、is-share: false
请求加解密CryptoFilter + api-decryptAES 加密 body；AES key 用 RSA 公钥包裹后放入 encrypt-key 头
验证码math 类型，Redis 存储Key global:captcha_codes:{uuid}
消息推送SSEmessage.transport: sse，路径 /resource/message，超时 86400000ms，心跳 60s
接口文档SpringDoc13 个分组：1.通用模块 … 13.任务调度模块
MCP 服务spring.ai.mcp路径 /mcp，协议 STREAMABLE
健康检查Actuator/actuator/** 需 HTTP Basic（admin/admin123），供 SBA 采集
跨域与安全Spring Security 过滤链统一异常处理、XSS 过滤、幂等/限流由框架 starter 提供

业务模块层

业务模块全部位于 iot-platform/iot-platform-modules，统一包前缀 org.dromara.iot。模块之间通过接口与事件解耦，共享 iot-platform-common 中的常量与枚举。

2permission三线权限：应用 / 数据集 / 分组及授权关系/iot/app、/iot/dataset、/iot/group
3collect设备数据上行（HTTP）、限流、消息组装/iot/collect/https
4monitor设备在线状态与服务器运行指标/iot/monitor/device、/iot/monitor/server

6archive档案分类、档案条目与附件/iot/archive
7report报表定义、生成与文件下载/iot/report
8deploy部署任务、应用/环境登记、GitHub 项目同步与授权/iot/deploy、/iot/deploy/github
9pay支付订单、退款、渠道配置与虚拟商品/iot/pay、/iot/pay/product
10ticket工单流转、流转记录与工单规则（对接 Warm-Flow）/iot/ticket、/iot/ticket/rule

12 个模块明细

device 产品 / 设备

维护产品分类、产品物模型与设备台账；设备编码 deviceCode 是全链路（MQTT 主题、Kafka 消息、ES 文档）的主键。

/iot/product · /iot/device · 前端 views/device

permission 三线权限

以「应用 → 数据集 → 分组」三线模型组织数据授权，控制不同账号可见的设备与数据范围。

/iot/app · /iot/dataset · /iot/group

collect 数据采集

提供 HTTP 上行入口，校验设备与报文后投递 Kafka；MQTT 侧由 MqttDeviceDataSubscriber 负责，二者最终一致。

/iot/collect/https/{deviceCode}

monitor 运行监控

设备在线状态（Redis 心跳 TTL 5 分钟）与服务器指标查询；页面侧结合 SBA 展示 JVM、线程与日志。

/iot/monitor/device · /iot/monitor/server

sso 统一认证

自研 Sa-Token OAuth2 Server + OIDC + CAS Server/Client。默认 clientId e5cd7e4891bf95d1d19206ce24a7b32e，ticket 有效期 300s。

/iot/sso · /iot/oauth2-client

archive 档案管理

档案分类树、档案条目与附件管理，附件走 MinIO / OSS 统一存储。

/iot/archive

report 报表 / 文件

报表模板与生成任务，支持按时间范围导出设备数据，产物落对象存储。

/iot/report

deploy 自动化部署

应用/环境登记、构建任务与发布记录；GitHub 项目同步支持公开与私有仓库，并按账号授权可见范围。

/iot/deploy · /iot/deploy/github

pay 聚合支付

支付订单、退款、渠道配置与虚拟商品，渠道参数落库并可热更新。

/iot/pay · /iot/pay/product

ticket 工单 / 流程

工单创建、流转记录与规则匹配，流程引擎使用 Warm-Flow。

/iot/ticket · /iot/ticket/rule

cloud 云平台纳管

云账号凭证、纳管资源清单与 Flink 作业管理，支持多类型云平台接入。

/iot/cloud/account · /iot/cloud/resource · /iot/cloud/flink

job 任务调度

业务任务定义与执行日志查询，调度执行由 SnailJob Server（8800/17888）承担。

/iot/job/info · /iot/job/log

通用能力层

iot-platform-common 只放常量、枚举与领域通用类型，不放业务逻辑，避免模块间循环依赖。

内容示例用途
常量Redis Key 前缀 iot:device:online:、iot:collect:limit:跨模块共享，避免硬编码
枚举设备状态、工单状态、部署任务状态数据库与前端字典统一取值
通用类型DeviceDataMessage 等消息体采集、消费、存储共用同一结构

框架底座

框架位于 thirdparty/iot-vue-plus，版本 6.0.0，作为父 POM 提供依赖管理。产品构建前必须先将其安装到本地 Maven 仓库。

分组内容提供的产品能力
iot-common-*core / web / json / log / oss / sms / mail / push / mqtt / ai / mcp / job / bom / doc加解密、日志、对象存储、短信邮件、MQTT 客户端、AI 与 MCP 接入
iot-modulessystem / demo / gen / job / workflow / ai用户角色菜单、代码生成、任务调度、Warm-Flow 工作流、AI 能力
iot-extendmonitor-admin / snailjob-server / snailai-serverSpring Boot Admin、SnailJob、SnailAI 三个独立控制台
 
# 首次构建顺序不可颠倒
cd d:/DevProjects/snail/thirdparty/iot-vue-plus
mvn -DskipTests clean install

cd d:/DevProjects/snail/iot-platform
mvn -Pprod -DskipTests clean package

模块依赖与构建

层级模块产物 / 依赖关系
框架thirdparty/iot-vue-plus产出 org.dromara:iot-vue-plus:6.0.0 到本地仓库
公共iot-platform-common被 12 个业务模块依赖
业务iot-platform-modules（12 个）依赖 common 与框架 starter
启动iot-platform-admin聚合全部模块，产出可执行 JAR 与 Docker 镜像

模块间不直接引用彼此的实现类；跨模块协作通过 common 中的类型或事件完成，新增模块时同步在 SpringDoc group-configs 中追加分组。
