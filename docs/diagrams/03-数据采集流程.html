Snail-IoT · 设备数据采集流程

MQTT / HTTP 上行 → EMQX → Kafka iot-device-data → ES 时序 + Redis 心跳 + 首次心跳回写 PostgreSQL

链路总览

设备 / 接入 中间件 / 检索 / 缓存 应用处理 关系型存储

逐跳说明：

跳组件输入输出 / 动作
1设备端传感器数据MQTT publish 或 HTTPS POST
2iot-emqxiot/device/{deviceCode}/#Broker 分发，允许匿名连接
3MqttDeviceDataSubscriberMQTT 消息取主题第 3 段为 deviceCode，组装 DeviceDataMessage
4DeviceDataKafkaProducerDeviceDataMessage发送到 Kafka topic iot-device-data
5DeviceDataKafkaConsumerKafka 消息解析后分发到 ES / Redis / PostgreSQL，最后手动 ack
6aElasticsearch原始报文写入索引 iot_device_data（Easy-ES）
6bRedisdeviceCodeSET iot:device:online:{code}，TTL 5 分钟
6cPostgreSQL首次心跳更新 iot_device.online_status / last_online_time

MQTT 接入

项值
Brokerlocalhost:1883（容器内 iot-emqx:1883）
WebSocketlocalhost:8083
上行主题iot/device/{deviceCode}/#
下行指令主题iot/command/{deviceCode}/#（常量已定义）
服务端订阅iot/device/+/#，QoS 1
客户端开关mqtt.client.enabled=true（compose 已设为 true）
客户端 IDiot-platform-server
认证EMQX_ALLOW_ANONYMOUS=true，当前无需账号
 
# 模拟设备上报（需本机有 mosquitto-clients；无则用 docker 镜像）
mosquitto_pub -h localhost -p 1883 ^
  -t "iot/device/DEV-TEMP-0001/telemetry" ^
  -m "{\"temperature\":25.6,\"humidity\":61}" -q 1

# Windows 下也可用 curl 走 WebSocket 之外的方式，或直接 POST HTTP 入口（见下节）
主题第 3 段必须存在且等于设备编码，否则订阅器记录 非法设备上报主题 并直接丢弃。例如 iot/device/DEV-TEMP-0001/telemetry 正确，iot/device/telemetry 会被丢弃。

HTTP 接入

面向无 MQTT 能力的设备（摄像头、PLC 网关）。入口方法在 DeviceCollectController，路径 POST /iot/collect/https/{deviceCode}，且带 @SaIgnore，不需要登录 Token。

项值
URL（容器内）http://iot-server:8080/iot/collect/https/{deviceCode}
URL（经统一入口）http://localhost/prod-api/iot/collect/https/{deviceCode}
请求头deviceSecret: {设备密钥}
请求体原始 JSON 字符串（@RequestBody String）
校验设备存在 → status=0（正常）→ 密钥匹配 → 限流
响应R.ok()；失败返回 设备不存在 / 设备已停用 / 设备密钥校验失败 / 上报过于频繁
 
curl -X POST "http://localhost/prod-api/iot/collect/https/DEV-PLC-0001" ^
  -H "Content-Type: application/json" ^
  -H "deviceSecret: secret-plc-0001" ^
  -d "{\"line\":\"A\",\"throughput\":120}"
deviceSecret 在 iot_device.device_secret 中维护，演示数据见 iot-platform/script/sql/postgres/iot_platform.sql：DEV-TEMP-0001 / secret-temp-0001、DEV-TEMP-0002 / secret-temp-0002、DEV-PLC-0001 / secret-plc-0001。生产环境应改为每设备独立密钥并轮换。

Kafka 缓冲

项值
Topiciot-device-data
保留常量iot-device-event（设备生命周期事件，预留）
消费组iot-platform
Ack 模式手动 Acknowledgment.acknowledge()，异常也会 ack 防止毒消息阻塞
容器内地址iot-kafka:9092
宿主机调试localhost:9094
模式KRaft 单节点，无 ZooKeeper，自动建 topic
 
# 查看 topic
docker exec -it iot-kafka /opt/kafka/bin/kafka-topics.sh ^
  --bootstrap-server localhost:9092 --list

# 消费最近 5 条（宿主机调试监听器）
docker exec -it iot-kafka /opt/kafka/bin/kafka-console-consumer.sh ^
  --bootstrap-server localhost:9092 --topic iot-device-data ^
  --from-beginning --max-messages 5

# 查看消费组积压
docker exec -it iot-kafka /opt/kafka/bin/kafka-consumer-groups.sh ^
  --bootstrap-server localhost:9092 --describe --group iot-platform

存储落点

Elasticsearch

项值
索引iot_device_data
文档字段id（UUID）、deviceCode、productCode、source、payload、timestamp、traceId
开关easy-es.enable；compose 中 EASY_ES_ENABLE=true，本地 dev 默认 false
索引创建首次消费时探测，不存在则自动创建，失败后下次重试
 
curl "http://localhost:9200/iot_device_data/_search?size=5&pretty"

Redis

Key值TTL
iot:device:online:{deviceCode}最后一次上报时间戳（毫秒）5 分钟，每次上报刷新
iot:collect:limit:{deviceCode}限流计数器（Redisson RateLimiter）60 秒窗口
 
docker exec -it ruoyi-redis redis-cli -a 123456 --no-auth-warning ^
  KEYS "iot:device:online:*"

docker exec -it ruoyi-redis redis-cli -a 123456 --no-auth-warning ^
  TTL "iot:device:online:DEV-TEMP-0001"

PostgreSQL

只在 Redis 心跳 Key 不存在（即设备刚上线）时回写一次，避免每条上报都更新数据库：

docker exec -it ruoyi-postgres psql -U postgres -d ruoyi -c ^
  "SELECT device_code, online_status, last_online_time FROM iot_device WHERE device_code = 'DEV-TEMP-0001';"

online_status：0 离线、1 在线、2 未知；status 为设备启停状态（0 正常）。

限流与鉴权

入口鉴权限流
MQTTEMQX 允许匿名（可配置认证）订阅器未做应用层限流，依赖 Broker 与 Kafka 削峰
HTTPdeviceSecret 请求头 + 设备状态校验（@SaIgnore 免登录）按设备维度 100 次 / 60 秒，超出返回「上报过于频繁」
前端 APIAuthorization: Bearer + clientid 头—
解耦思路：接入层只负责「收」，Kafka 负责「缓冲」，消费者负责「落」。新增统计 / 告警逻辑时，只需再订阅 iot-device-data，不影响设备端与接入层。

逐步验证

  1. Broker 就绪：docker logs iot-emqx --tail 50 出现 EMQX is started!。
  2. 服务端已订阅：docker logs iot-server | findstr "已订阅 MQTT"。
  3. 发一条 MQTT：用上面的 mosquitto_pub 命令，主题带 DEV-TEMP-0001。
  4. Kafka 有消息：kafka-console-consumer 能读到 JSON。
  5. Redis 有心跳：KEYS iot:device:online:* 返回该 Key，TTL ≤ 300。
  6. ES 有文档：_search 返回 hits.total.value 增长。
  7. 库里有上线时间：last_online_time 更新为刚才时间。
  8. HTTP 入口：用 curl 调 /prod-api/iot/collect/https/DEV-PLC-0001，返回 code=200。
  9. 限流生效：1 分钟内连续请求超过 100 次，出现「上报过于频繁，请稍后再试」。

常见问题

现象原因处理
消息发出但 Kafka 无数据主题格式不对，第 3 段不是设备编码改为 iot/device/{deviceCode}/xxx
Kafka 无数据且服务端无订阅日志MQTT_CLIENT_ENABLED=falsecompose 中设为 "true" 并重启 iot-server
ES 查不到文档EASY_ES_ENABLE=false 或索引创建失败设为 true；查看 iot-server 日志中的 ES 报错
Redis 无在线 Key消费者未消费到消息检查消费组积压与 iot-server 日志
HTTP 返回「设备密钥校验失败」deviceSecret 与库中不一致查 iot_device.device_secret
设备上线时间不更新Redis Key 仍存在（5 分钟内重复上报）属正常设计，仅首次心跳回写数据库
