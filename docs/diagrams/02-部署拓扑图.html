网络模型

编排分两层：根目录 docker-compose.yml 只启动 PostgreSQL 与 Redis；业务编排 iot-platform/script/docker/docker-compose.yml 通过外部网络复用它们。

层文件网络声明启动命令
基础设施层根目录 docker-compose.yml未声明 networks，使用默认网络docker compose -p devprojects -f docker-compose.yml up -d
业务层iot-platform/script/docker/docker-compose.ymlexternal: true, name: devprojects_defaultdocker compose -p devprojects -f script/docker/docker-compose.yml up -d --build
项目名必须是 devprojects：Compose 默认用目录名作为项目名生成网络（如 snail_default），与外部网络名 devprojects_default 不一致会直接报 network devprojects_default declared as external, but could not be found。 
# 1) 先起基础设施（会自动创建 devprojects_default）
docker compose -p devprojects -f docker-compose.yml up -d

# 2) 确认网络已存在
docker network ls | findstr devprojects_default

# 3) 再起业务编排
docker compose -p devprojects -f iot-platform/script/docker/docker-compose.yml up -d --build

# 4) 统一查看状态
docker compose -p devprojects -f iot-platform/script/docker/docker-compose.yml ps

同网络内以服务名互访：ruoyi-postgres、ruoyi-redis、iot-kafka:9092、iot-emqx:1883、iot-sba:9090。宿主调试时才用 localhost:映射端口。

Nginx 路由

唯一配置文件：iot-platform/plus-ui/nginx.conf，随前端镜像一起打包，容器启动即生效。

路径upstream转发目标特性
/prod-api/iot-server:8080去掉 /prod-api 前缀proxy_buffering off（SSE 必需）、读超时 86400s
/admin/iot-sba:9090保留 /adminSpring Boot Admin
/snail-job/iot-snailjob:8800保留前缀任务调度控制台
/snail-ai/iot-snailai:8900保留前缀AI 控制台
/jenkins-api/host.docker.internal:8090去掉前缀Basic 认证 admin:admin123（硬编码，生产须改）
/本地静态目录index.html 回退Vue history 路由
  • client_max_body_size 100m：报表 / 附件上传上限。
  • Actuator 端点（/prod-api/actuator/**）在 Nginx 层直接返回 403。
  • /jenkins-api/ 的 Basic 凭据为 YWRtaW46YWRtaW4xMjM=，即 admin:admin123。

启动顺序

阶段动作判定就绪
1启动 ruoyi-postgres / ruoyi-redispg_isready 成功、redis-cli -a 123456 ping 返回 PONG
2启动 iot-elasticsearch / iot-kafkaES 9200 可连；Kafka --list 成功（healthcheck 通过）
3启动 iot-servercurl http://localhost:8080/actuator/health 或容器日志出现 Started
4启动 iot-sba9090 可访问
5启动 iot-snailjob / iot-snailai8800 / 8900 可访问，客户端完成注册
6启动 iot-webhttp://localhost 返回登录页
 
# 只重建后端（改了 Java 代码后）
docker compose -p devprojects -f iot-platform/script/docker/docker-compose.yml up -d --build iot-server

# 只重建前端（改了 plus-ui）
docker compose -p devprojects -f iot-platform/script/docker/docker-compose.yml up -d --build iot-web

# 查看某容器最近日志
docker logs --tail 200 -f iot-server

Kubernetes

部署脚本：iot-platform/script/k8s/deploy.sh，通过 dev / prod 两个环境参数隔离命名空间与端口。

项devprod
命名空间iot-platform-deviot-platform-prod
前端 NodePort3008030081
组件范围精简栈：postgres + redis + iot-server + iot-web全量栈：另含 ES / Kafka / EMQX / MinIO / Nacos / SBA / SnailJob / SnailAI
镜像拉取imagePullPolicy: IfNotPresent同左
数据库初始化db-init-job.yaml + iot_schema_history 台账同左
 
# 部署
bash iot-platform/script/k8s/deploy.sh dev
bash iot-platform/script/k8s/deploy.sh prod

# 访问
http://127.0.0.1:30080/     # dev
http://127.0.0.1:30081/     # prod

# 常用排查
kubectl -n iot-platform-dev get pod,svc
kubectl -n iot-platform-dev logs deploy/iot-server --tail=100
kubectl -n iot-platform-dev get job
dev 精简栈不部署 SBA / SnailJob / SnailAI 实例，但保留了同名 占位 ClusterIP Service，用于保证 Nginx upstream 的 DNS 可解析。此时 /admin、/snail-job、/snail-ai 返回 502 属预期行为。

敏感配置集中在 Secret iot-secret（POSTGRES_USERNAME、POSTGRES_PASSWORD、REDIS_PASSWORD、MINIO_ROOT_USER、MINIO_ROOT_PASSWORD、GITHUB_TOKEN），默认值与本地一致，见 04 · K8s Secret。
