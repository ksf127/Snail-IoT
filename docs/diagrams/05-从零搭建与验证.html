Snail-IoT · 从零搭建与验证

从空机器到可登录、可采集、可观测的完整链路：环境 → 中间件 → 数据库 → 构建 → 启动 → 验证 → 排障

全程按 0 → 10 顺序执行即可。只想跑通最小链路时，第 1 步只起 postgres + redis，第 7/8 步可跳过。

0 · 环境准备

组件版本要求校验命令
JDK21java -version
Maven3.9+mvn -v
Node.js≥ 20.19node -v
pnpm≥ 10pnpm -v
Docker Desktop含 Compose v2docker compose version
kubectl可选，K8s 部署需要kubectl version --client

1 · 启动中间件

1.1 最小链路（PostgreSQL + Redis）

cd d:/DevProjects/snail
docker compose -p devprojects up -d

docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"
# ruoyi-postgres   Up   0.0.0.0:5432->5432/tcp
# ruoyi-redis      Up   0.0.0.0:6379->6379/tcp

根编排只有 postgres 与 redis，其中 PostgreSQL 首次启动会自动执行 init-vector.sql 创建 vector 扩展。

1.2 全量业务编排（采集 / 调度 / 监控 / 对象存储）

docker network ls | findstr devprojects_default

3 · 构建后端

产品 POM 的父 POM 是 org.dromara:iot-vue-plus:6.0.0，且 relativePath 为空。未先安装框架时会报 Non-resolvable parent POM。 
# ① 安装框架底座到本地仓库（首次必须）
cd d:/DevProjects/snail/thirdparty/iot-vue-plus
mvn -DskipTests clean install

# ② 构建产品
cd d:/DevProjects/snail/iot-platform
mvn -Pprod -DskipTests clean package

# 产物
# iot-platform/iot-platform-admin/target/iot-platform-admin.jar

Windows 沙箱下若 Maven 无法写入默认仓库/用户目录，追加：

mvn -Pprod -DskipTests clean package ^
  "-Dmaven.repo.local=C:\Users\ThinkPad\.m2\repository" ^
  "-Duser.home=D:\DevProjects\snail\.mvn-home"

6 · 逐步验证

6.1 登录与鉴权

1
打开前端 http://localhost，用 admin / admin123 登录，能进入首页且左侧菜单完整。
2
验证数据权限 用 test / 666666（本部门及以下）与 test1 / 666666（仅本人）分别登录，菜单与数据范围应不同。
3
验证 clientid 浏览器 DevTools 中请求头应同时含 Authorization: Bearer ... 与 clientid: e5cd7e4891bf95d1d19206ce24a7b32e。

6.2 业务模块

4
设备台账 「设备管理 → 设备列表」应看到 3 台演示设备（DEV-TEMP-0001/0002、DEV-PLC-0001）。
5
产品物模型 「产品管理」应看到 P-SENSOR-TEMP、P-GATEWAY-PLC，可打开物模型定义。
6
其余模块 依次点开权限、档案、报表、部署、支付、工单、云平台、任务调度，页面无 500 / 空白。

6.3 HTTP 采集链路

curl -X POST "http://localhost:8080/iot/collect/https/DEV-PLC-0001" ^
  -H "Content-Type: application/json" ^
  -H "deviceSecret: secret-plc-0001" ^
  -d "{\"line\":\"A\",\"throughput\":120}"

# 期望响应：{"code":200,"msg":"操作成功"}
校验点命令 / 位置期望
Kafka 有消息docker exec -it iot-kafka kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic iot-device-data --from-beginning --max-messages 1输出含 deviceCode、source=HTTPS
ES 已落库curl "http://localhost:9200/iot_device_data/_search?size=1&pretty"hits.total.value ≥ 1
Redis 在线状态docker exec -it ruoyi-redis redis-cli -a 123456 --no-auth-warning KEYS "iot:device:online:*"存在 iot:device:online:DEV-PLC-0001
PostgreSQL 回写SELECT device_code, online_status, last_online_time FROM iot_device WHERE device_code='DEV-PLC-0001';online_status='1'，时间已更新
回写只在 Redis 在线 Key 不存在时触发（首次心跳）。重复上报时 last_online_time 不会每次都变，这是设计行为。

6.4 MQTT 采集链路

# 容器内发布（主题第三段即 deviceCode）
docker exec -it iot-emqx emqx pub -t "iot/device/DEV-TEMP-0001/telemetry" -m "{\"temp\":26.5}" -q 1

# 或宿主机安装 mosquitto 客户端
mosquitto_pub -h localhost -p 1883 -t "iot/device/DEV-TEMP-0001/telemetry" -m "{\"temp\":26.5}" -q 1

订阅器订阅 iot/device/+/#（QoS 1），解析第 3 段为 deviceCode；消息经 Kafka 进入同一消费链路，验证方式同 6.3。MQTT 订阅器未做应用层限流。

6.5 平台能力

7

8

9
Spring Boot Admin 打开 http://localhost:9090（admin/admin123），iot-platform 实例已注册。
10
MinIO 打开 http://localhost:9001（ruoyi/ruoyi123），桶 ruoyi 存在且可匿名下载。
11
SSO 访问 /oauth2/authorize 或 /cas/login，能完成授权码 / 票据换取；默认 clientId e5cd7e4891bf95d1d19206ce24a7b32e。

9 · 排障

现象原因处理
Non-resolvable parent POM: org.dromara:iot-vue-plus:6.0.0未安装框架先在 thirdparty/iot-vue-plus 执行 mvn clean install
Maven 写入 D:\DevTools\maven 失败仓库 / 用户目录受限追加 -Dmaven.repo.local 与 -Duser.home
启动报 Redis NOAUTHdev 未配 Redis 密码补 spring.data.redis.password: 123456
启动连不上 PostgreSQLdev 硬编码 localhost:5432docker compose -p devprojects up -d postgres
业务编排报网络不存在devprojects_default 未创建先跑根编排，或统一加 -p devprojects
接口 401 /「客户端ID与Token不匹配」缺 clientid 头或与 Token 不一致确认前端 VITE_APP_CLIENT_ID 与登录 Token 一致
接口解密失败RSA 公私钥不匹配对齐 .env 与后端 api-decrypt
验证码不显示Redis 不通检查 Redis 状态与密码
ES 无数据easy-es.enable=false置为 true 并重启（K8s dev 精简栈默认关闭）
MQTT 不触发消费mqtt.client.enabled=false置为 true，并确认主题第三段为 deviceCode
Nacos 相关类找不到未激活 nacos profilemvn -Pnacos ... 或 --spring.profiles.active=dev,nacos
SSE 连不上Nginx 缓冲未关闭确认 /prod-api/ 段配置 proxy_buffering off
K8s 前端 502后端未就绪或 upstream 解析失败查 iot-web 的 wait-backends 与占位 Service
pnpm dev 端口占用默认 80关闭占用进程或改 VITE_APP_PORT

10 · 验收清单

  • 框架 mvn install 成功，产品 mvn package 产出可执行 jar

  • SnailJob / Spring Boot Admin / MinIO / EMQX 控制台均可登录
  • SSE 消息通道可用，Nginx 反向代理四个入口均正常
  • Docker 全量栈或 K8s dev/prod 至少一套部署成功并可登录
