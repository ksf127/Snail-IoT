> 本文描述 Snail-IoT 的总体架构、技术选型、运行拓扑、关键链路与模块划分，内容以当前仓库代码为准。

## 1. 总体定位

Snail-IoT 是一个面向物联网场景的一体化平台，覆盖 **设备接入 → 数据采集 → 存储检索 → 业务管理 → 监控调度 → 对外服务** 的完整链路，并内置统一认证、聚合支付、工单、云平台纳管与 AI 智能体能力。

平台采用“**框架底座 + 业务产品**”的分层结构：

- **框架底座（thirdparty/iot-vue-plus 6.0.0）**：提供 Spring Boot 4 基础能力、通用模块、Sa-Token 鉴权、代码生成、监控/调度接入等；以 Maven 父 POM 形式被产品继承。
- **业务产品（iot-platform 1.0.0）**：在框架之上实现 IoT 领域能力，独立打包部署。
- **AI 平台（thirdparty/snail-ai 1.1.1）**：独立服务，提供 Agent / RAG / MCP 能力。

## 4. 运行拓扑

### 4.1 Docker Compose（两层编排）

| 编排 | 文件 | 内容 |
| --- | --- | --- |
| 根编排 | [docker-compose.yml](file:///d:/DevProjects/snail/docker-compose.yml) | `ruoyi-postgres`（pgvector/pg16，5432）、`ruoyi-redis`（redis:7-alpine，6379，密码 `123456`） |
| 业务编排 | [script/docker/docker-compose.yml](file:///d:/DevProjects/snail/iot-platform/script/docker/docker-compose.yml) | Nacos、ES、Kafka、EMQX、MinIO、iot-server、iot-sba、iot-snailjob、iot-snailai、iot-web |

根编排**未声明 networks**，Docker Compose 会按项目名创建默认网络；业务编排声明：

```yaml
networks:
  default:
    external: true
    name: devprojects_default
```

由于仓库目录名为 `snail`，默认项目名会得到 `snail_default`。因此启动根编排必须显式指定项目名：

```bash
docker compose -p devprojects -f docker-compose.yml up -d
```

业务编排同样建议带 `-p devprojects`（或设置 `COMPOSE_PROJECT_NAME=devprojects`），以便网络与容器命名一致。

### 4.2 Nginx 统一入口

主项目唯一的 Nginx 配置是 [plus-ui/nginx.conf](file:///d:/DevProjects/snail/iot-platform/plus-ui/nginx.conf)，随 `iot-platform/plus-ui:1.0.0` 镜像发布，监听容器 80 端口：

| 路径 | 上游 | 说明 |
| --- | --- | --- |
| `/` | 静态资源 | SPA `try_files` 回退 `index.html` |
| `/prod-api/` | `iot-server:8080` | **去掉 `/prod-api` 前缀**，`proxy_buffering off`，读超时 86400s（兼容 SSE） |
| `/admin/` | `iot-sba:9090` | Spring Boot Admin |
| `/snail-job/` | `iot-snailjob:8800` | SnailJob 控制台 |
| `/snail-ai/` | `iot-snailai:8900` | SnailAI 控制台 |
| `/jenkins-api/` | `host.docker.internal:8090` | Jenkins，Nginx 注入 Basic 认证 |
| `/actuator` 等 | — | 直接 `403` |

其他要点：`client_max_body_size 100m`、gzip、`server_tokens off`。

### 4.3 Kubernetes

同一集群内按环境划分命名空间，前端入口使用不同 NodePort：

| 环境 | 命名空间 | 前端入口 | 部署内容 |
| --- | --- | --- | --- |
| dev | `iot-platform-dev` | http://localhost:30080/ | 精简栈：postgres + redis + iot-server + iot-web（ES/MQTT 关闭） |
| prod | `iot-platform-prod` | http://localhost:30081/ | 全量栈：全部中间件 + 5 个应用 |

dev 精简栈下，`iot-sba` / `iot-snailjob` / `iot-snailai` 没有实际 Pod，但会创建**占位 ClusterIP Service**，保证 Nginx upstream 的 DNS 可解析。详见 [02 · 部署指南](file:///d:/DevProjects/snail/docs/02-部署指南.md)。

## 5. 核心链路

### 5.1 登录与鉴权

```
前端登录页
  │ ① RSA 加密 AES Key（encrypt-key 头）+ AES 加密请求体
  ▼
CryptoFilter ──▶ POST /auth/login ──▶ IAuthStrategy
  │                                   ├─ password / social / sms / email / xcx
  │                                   └─ 校验验证码（Redis global:captcha_codes:{uuid}）
  ▼
Sa-Token 登录（SaLoginParameter.extra 写入 clientId）──▶ JWT
  │
  ▼
后续请求：Authorization: Bearer <token> + clientid 头
  │
  ▼
SaInterceptor 校验 clientid 与 Token extra 一致
（不一致返回「客户端ID与Token不匹配」）
```

关键配置（[application.yml](file:///d:/DevProjects/snail/iot-platform/iot-platform-admin/src/main/resources/application.yml)）：

- `sa-token.token-name: Authorization`、`token-prefix: Bearer`
- `is-concurrent: true`、`is-share: false`、JWT `jwt-secret-key`
- `security.excludes`：静态资源、`/error`、`/*/api-docs/**`、`/snail-chat/**`、`/iot/pay/notify/**` 等
- 验证码：`captcha.enable=true`、`type=math`
- 密码策略：`user.password.maxRetryCount=5`、`lockTime=10`
- 接口加密：`api-decrypt.enabled=true`（`@ApiEncrypt` 标注的接口生效）

### 5.2 设备采集

采集支持 MQTT 与 HTTP 两条上行通道，统一经 Kafka 缓冲：

```
设备端
  │ MQTT publish  topic: iot/device/{deviceCode}/#
  ▼
EMQX 5.8.4 ──▶ MqttDeviceDataSubscriber（mqtt.client.enabled=true 时生效）
                    │ 取 topic 第 3 段为 deviceCode，组装 DeviceDataMessage
                    ▼
             DeviceDataKafkaProducer ──▶ Kafka topic: iot-device-data
                                                │
                                                ▼
                                  DeviceDataKafkaConsumer（groupId: iot-platform，手动 ack）
                                                │
                       ┌────────────────────────┼─────────────────────────┐
                       ▼                        ▼                         ▼
        Elasticsearch 索引 iot_device_data   Redis 心跳                 PostgreSQL
        （Easy-ES，easy-es.enable=false       iot:device:online:       仅首次心跳时
          时跳过写入）                         {deviceCode}，TTL 5 分钟   更新设备在线状态
```

HTTP 通道：`POST /iot/collect/https/{deviceCode}`，请求体为设备数据，同样投递 Kafka。

设计要点：

1. **解耦削峰**：MQTT 订阅与入库之间由 Kafka 缓冲，避免突发流量压垮数据库。
2. **时序与状态分离**：设备数据写 Elasticsearch；在线状态用 Redis 心跳判断，仅在首次心跳时回写 PostgreSQL，避免每次上报都更新关系库。
3. **限流**：采集入口按 `iot:collect:limit:` 前缀限流，默认 100 次 / 60 秒。
4. **默认关闭**：`easy-es.enable` 与 `mqtt.client.enabled` 在 prod 中均由环境变量控制，默认 `false`，需要时显式开启。

> 可视化流程见 [diagrams/03-数据采集流程.html](file:///d:/DevProjects/snail/docs/diagrams/03-数据采集流程.html)。

### 5.3 统一消息推送（SSE）

| 配置 | 值 |
| --- | --- |
| `message.transport` | `sse` |
| `message.path` | `/resource/message` |
| 超时 | `86400000` ms |
| 心跳 | `60` s |

前端通过 `.env.*` 的 `VITE_APP_MESSAGE_ENABLED=true`、`VITE_APP_MESSAGE_TRANSPORT=sse`、`VITE_APP_MESSAGE_PATH=/resource/message` 对接；Nginx `/prod-api/` 已关闭响应缓冲并设置长超时，保证 SSE 不被截断。WebSocket 未启用。

### 5.4 统一认证（SSO）

`iot-platform-sso` 基于 Sa-Token 自研三种协议：

| 协议 | 端点 |
| --- | --- |
| OAuth2 | `/oauth2/authorize`、`/oauth2/token`、`/oauth2/refresh`、`/oauth2/revoke`、`/oauth2/client_token`、`/oauth2/doLogin`、`/oauth2/doConfirm`、`/oauth2/userinfo` |
| OIDC | `/.well-known/openid-configuration`（元数据） |
| CAS | `/cas/login`、`/cas/serviceValidate`、`/cas/p3/serviceValidate`、`/cas/logout` |
| 平台票据 | `/iot/sso/ticket`、`/iot/sso/exchange`、`/iot/sso/validate`、`/iot/sso/sessions`、`/iot/sso/logout` |
| CAS 客户端 | `/iot/sso/cas/ticket`、`/iot/sso/cas-client/login`、`/iot/sso/cas-callback` |

票据与客户端信息存储：

- 客户端表 `iot_oauth2_client`（前端页面 `views/iot/oauth2Client`）
- Redis 键前缀：`iot:sso:ticket:`、`iot:sso:cas:st:`、`iot:sso:session:`

关键配置：

```yaml
iot:
  sso:
    server-url: http://localhost:8080
    login-url: http://localhost/cas-login
    confirm-url: http://localhost/oauth2-confirm
    default-client-id: e5cd7e4891bf95d1d19206ce24a7b32e
    ticket-timeout: 300
    oidc:
      id-token-timeout: 3600
    client:
      enabled: false
      service: http://localhost:8080/iot/sso/cas-callback
```

### 5.5 自动化部署与 GitHub 项目

`iot-platform-deploy` 提供部署任务、应用登记、环境登记与 GitHub 项目管理：

| 能力 | 端点 | 说明 |
| --- | --- | --- |
| 部署任务 | `GET /iot/deploy/list`、`POST /iot/deploy/release`、`POST /iot/deploy/task/build`、`PUT /iot/deploy/task/{taskId}/finish`、`DELETE /iot/deploy/task/{taskIds}`、`GET /iot/deploy/{taskId}/log` | 触发 Jenkins 构建、回写状态、查看实时日志 |
| 应用管理 | `/iot/deploy/app`（list/page/{appId}/POST/PUT/DELETE） | 构建配置登记 |
| 环境管理 | `/iot/deploy/env`（list/page/{envId}/POST/PUT/DELETE） | dev / prod 目标环境 |
| GitHub 项目 | `GET /iot/deploy/github/page`、`POST /iot/deploy/github/sync`、`GET/PUT /iot/deploy/github/{repoId}/users` | 同步仓库列表、按账号授权可见项目 |

GitHub 同步两种模式：

- **无 Token**：调用 `/users/{owner}/repos`，仅能获取公开仓库；
- **有 Token**：`iot.github.token=${GITHUB_TOKEN:}` 非空时调用 `/user/repos?affiliation=owner&visibility=all` 并携带 `Authorization: Bearer`，可同步该账号的私有仓库。

前端「自动化部署」页包含 4 个 Tab：部署任务 `task`、应用管理 `app`、GitHub 项目 `github`、环境管理 `env`。

## 6. 权限模型（三线交汇）

平台权限由三条线组成，在授权时交汇：

| 线 | 实体 | 含义 |
| --- | --- | --- |
| 数据线-分组 | `IotGroup` | 设备的物理/逻辑分组 |
| 数据线-数据集 | `IotDataset` | 面向分析的数据集合 |
| 服务线-应用 | `IotApp` | 对外提供服务的应用 |

关联表：`IotAppDataset`（应用-数据集）、`IotAppRole`（应用-角色）、`IotDatasetRole`（数据集-角色）。

通过角色作为纽带，实现“**某角色可访问哪些应用/数据集/分组**”的细粒度授权；系统菜单与按钮权限仍由框架 `sys_menu` / `sys_role_menu` 管理。

## 7. 聚合支付

`iot-platform-pay` 采用**渠道工厂**模式，渠道实现可插拔：

```
PayController ──▶ IotPayService ──▶ PayChannelFactory
                                        │
                          ┌─────────────┼──────────────┐
                          ▼             ▼              ▼
                   MockPayChannel  AliQrPayChannel  WxNativePayChannel
                          └─────────── IPayChannel（可插拔扩展）
```

- 统一模型：`IotPayOrder`（订单）、`IotPayRefund`（退款）、`IotPayChannelConfig`（渠道配置）、`IotPayProduct`（虚拟商品）
- 统一结果：`PrePayResult` / `PayNotifyResult` / `RefundResult`
- 回调免鉴权路径：`/iot/pay/notify/**`（在 `security.excludes` 中放行）
- 虚拟商品：下单时以服务端商品价格为准，避免客户端篡改金额

## 8. 监控与调度

| 组件 | 容器 | 端口 | 作用 |
| --- | --- | --- | --- |
| Spring Boot Admin | `iot-sba` | 9090 | 应用健康、指标、日志查看（`/admin`） |
| SnailJob Server | `iot-snailjob` | 8800 / 17888 | 任务调度中心 Dashboard 与客户端通信 |
| SnailAI Server | `iot-snailai` | 8900 / 18888 | AI 控制台与 gRPC 服务 |

业务后端 `iot-server` 作为客户端注册到上述三个中心（dev 中 SBA/SnailJob 关闭，SnailAI 开启）。

任务调度双轨：

- **本地调度**：`IotJobScheduler` 基于 `ThreadPoolTaskScheduler`，支持 `CRON` / `FIXED_RATE`；
- **分布式调度**：`IotJobDispatchExecutor`（`@JobExecutor(name = "iotJobDispatch")`）把 SnailJob 触发转交 `IotJobInvoker`；
- `snail-job.enabled` dev 关闭、prod 开启；执行器组 `ruoyi_group`，命名空间取 `spring.profiles.active`。
