# 01 · 系统架构设计

> 本文描述 Snail-IoT 的总体架构、技术选型、数据链路与模块划分。
> 配套可视化图表见 [diagrams/01-系统架构图.html](file:///d:/DevProjects/snail/docs/diagrams/01-系统架构图.html)。

---

## 1. 总体定位

Snail-IoT 是一个面向物联网场景的一体化平台，覆盖 **设备接入 → 数据采集 → 存储检索 → 业务管理 → 监控调度 → 对外服务** 的完整链路，并内置统一认证、聚合支付与 AI 智能体能力。

平台采用“**框架底座 + 业务产品**”的分层结构：

- **框架底座（thirdparty/iot-vue-plus）**：提供 Spring Boot 4 基础能力、通用模块、Sa-Token 鉴权、代码生成、监控/调度接入等；以 Maven 父 POM 形式被产品继承。
- **业务产品（iot-platform）**：在框架之上实现 IoT 领域能力，独立打包部署。

## 4. 核心数据链路（设备采集）

设备数据从接入到可检索，经过三级缓冲与双写：

```
设备端
  │ publish (MQTT)
  ▼
EMQX 5.8.4  ──(topic: iot/device/+/data)──▶  MqttDeviceDataSubscriber (mica-mqtt)
                                                    │
                                                    │ 组装 DeviceDataMessage
                                                    ▼
                                        DeviceDataKafkaProducer ──▶ Kafka topic
                                                                        │
                                                                        ▼
                                                          DeviceDataKafkaConsumer
                                                                   │
                                          ┌────────────────────────┴────────────────────┐
                                          ▼                                             ▼
                            PostgreSQL（业务/最新值/关系）              Elasticsearch（IotDeviceDataDoc 时序）
                                     MyBatis-Plus                          Easy-ES (IotDeviceDataEsMapper)
```

**设计要点**

1. **解耦**：MQTT 订阅与入库之间用 Kafka 解耦，避免突发流量压垮数据库。
2. **双写分工**：PostgreSQL 存关系型数据与设备维度信息；Elasticsearch 承担高频时序写入与多维检索。
3. **可扩展**：`DeviceCollectController` 同时提供 HTTP 采集入口，便于不支持 MQTT 的第三方系统接入。

> 可视化流程见 [diagrams/03-数据采集流程.html](file:///d:/DevProjects/snail/docs/diagrams/03-数据采集流程.html)。

## 5. 权限模型（三线交汇）

平台权限由三条线组成，在授权时交汇：

| 线 | 实体 | 含义 |
| --- | --- | --- |
| 数据线-分组 | `IotGroup` | 设备的物理/逻辑分组 |
| 数据线-数据集 | `IotDataset` | 面向分析的数据集合 |
| 服务线-应用 | `IotApp` | 对外提供服务的应用 |

关联表：`IotAppDataset`（应用-数据集）、`IotAppRole`（应用-角色）、`IotDatasetRole`（数据集-角色）。
通过角色作为纽带，实现“**某角色可访问哪些应用/数据集/分组**”的细粒度授权。

## 6. 统一认证（SSO）

`iot-platform-sso` 模块提供三种协议的统一认证，服务于平台内部与第三方系统：

- **CAS**：[CasController](file:///d:/DevProjects/snail/iot-platform/iot-platform-modules/iot-platform-sso/src/main/java/org/dromara/iot/sso/controller/CasController.java) + `CasTicket`
- **OAuth2**：[OAuth2Controller](file:///d:/DevProjects/snail/iot-platform/iot-platform-modules/iot-platform-sso/src/main/java/org/dromara/iot/sso/controller/OAuth2Controller.java) + `IotOAuth2Configuration` / `DbSaOAuth2DataLoader`
- **OIDC**：基于 OAuth2 扩展，`iot.sso.oidc.id-token-timeout` 控制 ID Token 有效期
- **SSO 票据交换**：[SsoController](file:///d:/DevProjects/snail/iot-platform/iot-platform-modules/iot-platform-sso/src/main/java/org/dromara/iot/sso/controller/SsoController.java) 提供 ticket 签发与兑换

关键配置集中在 `iot.sso`（见 [application.yml](file:///d:/DevProjects/snail/iot-platform/iot-platform-admin/src/main/resources/application.yml)）：

```yaml
iot:
  sso:
    server-url: http://localhost:8080
    default-client-id: e5cd7e4891bf95d1d19206ce24a7b32e
    ticket-timeout: 300
    oidc:
      id-token-timeout: 3600
```

## 7. 聚合支付

`iot-platform-pay` 采用**渠道工厂**模式，渠道实现可插拔：

```
PayController ──▶ IotPayService ──▶ PayChannelFactory
                                        │
                          ┌─────────────┼─────────────┐
                          ▼             ▼             ▼
                      IPayChannel   MockPayChannel  (微信/支付宝 可扩展)
```

- 统一模型：`IotPayOrder`（订单）、`IotPayRefund`（退款）、`IotPayChannelConfig`（渠道配置）
- 统一结果：`PrePayResult` / `PayNotifyResult` / `RefundResult`
- 回调免鉴权路径：`/iot/pay/notify/**`（在 `security.excludes` 中放行）

## 8. 监控与调度

| 组件 | 容器 | 端口 | 作用 |
| --- | --- | --- | --- |
| Spring Boot Admin | `iot-sba` | 9090 | 应用健康、指标、日志查看（`/admin`） |
| SnailJob Server | `iot-snailjob` | 8800 / 17888 | 任务调度中心 Dashboard 与客户端通信 |
| SnailAI Server | `iot-snailai` | 8900 / 18888 | AI 控制台与 gRPC 服务 |

> 三者均为框架/上游组件自带控制台，默认账号统一 `admin` / `admin123`；经前端 80 端口的访问入口分别为 `/admin`、`/snail-job`、`/snail-ai`，详见 [04 · 账号与初始化说明](file:///d:/DevProjects/snail/docs/04-账号与初始化说明.md)。
