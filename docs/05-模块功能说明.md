## 5. collect · 数据采集

**职责**：设备数据上行接入、Kafka 缓冲、Elasticsearch 时序落库、Redis 在线心跳。

| 类 | 说明 |
| --- | --- |
| `MqttDeviceDataSubscriber` | 订阅 EMQX 主题 `iot/device/+/#`（mica-mqtt），组装消息 |
| `DeviceCollectController` | HTTP 采集入口，前缀 `/iot/collect/https`，`POST /{deviceCode}` |
| `DeviceDataKafkaProducer` | 将采集消息投递到 Kafka `iot-device-data` |
| `DeviceDataKafkaConsumer` | 消费 Kafka（groupId `iot-platform`，手动 ack） |
| `IotDeviceDataEsMapper` | Easy-ES 时序索引 Mapper（索引 `iot_device_data`） |
| `IotDeviceDataDoc` | ES 文档模型 |
| `DeviceDataMessage` | 采集消息载体 |

**数据链路**：

```
设备 ──MQTT──▶ EMQX（iot/device/{deviceCode}/#）──▶ MqttDeviceDataSubscriber ──▶ Kafka(iot-device-data)
                                                                                      │
                                                                                      ▼
                                                                        DeviceDataKafkaConsumer
                                                                          ├─▶ Elasticsearch(iot_device_data)  时序检索（easy-es.enable=true 时）
                                                                          └─▶ Redis(iot:device:online:{deviceCode}) 心跳，TTL 5 分钟
                                                                                   └─ 首次心跳时回写 PostgreSQL 设备在线状态
```

**要点**：

- HTTP 接入：`POST /iot/collect/https/{deviceCode}`，与 MQTT 共用同一 Kafka 通道。
- Kafka：`acks=1`、`retries=3`、`auto-offset-reset=latest`、`enable-auto-commit=false`、`ack-mode=manual_immediate`。
- ES 写入受 `easy-es.enable` 控制，prod 默认 `false`（关闭时不落库）。
- 设备在线判定以 Redis 心跳 key 为准（5 分钟 TTL），仅在首次心跳时更新 PostgreSQL 中的设备状态，避免高频写库。
- 采集限流：`iot:collect:limit:` 前缀，100 次 / 60 秒。

```yaml
iot:

    default-client-id: e5cd7e4891bf95d1d19206ce24a7b32e
    ticket-timeout: 300
    oidc:
      id-token-timeout: 3600
    client:
      enabled: false
      service: http://localhost:8080/iot/sso/cas-callback
```

前端页面：`views/iot/oauth2Client/index.vue`（客户端管理）、`views/iot/ssoSession/index.vue`（全平台会话与全局登出）；接口封装 `src/api/oauth2Client.js`、`src/api/ssoSession.js`。

## 12. ticket · 工单管理

**职责**：工单全生命周期管理，支持三类工单与两种引擎编排：

| 工单类型 | 说明 |
| --- | --- |
| `normal` 普通工单 | 人工流转（受理 → 处理 → 完成/关闭/驳回） |
| `rule` 规则工单 | 提交时触发 **LiteFlow 规则引擎**，按规则命中自动分配/调整优先级/自动关闭 |
| `flow` 流程工单 | 提交时发起 **Warm-Flow 审批流程**，按流程任务办理并回写状态 |

| 类 | 类型 | 说明 |
| --- | --- | --- |
| `IotTicketController` | 控制器 | 前缀 `/iot/ticket` |
| `IotTicketRuleController` | 控制器 | 前缀 `/iot/ticket/rule`，规则配置 CRUD |
| `IotTicketService` / `IotTicketServiceImpl` | 服务 | 工单编排：状态机流转 + 规则引擎 + 流程引擎 |
| `IotTicketRuleService` / `IotTicketRuleServiceImpl` | 服务 | 规则配置维护 |
| `IotTicket` / `IotTicketRecord` / `IotTicketRule` | 实体 | 工单 / 流转记录 / 规则 |
| `TicketRuleContext` + `TicketRule*Component` | LiteFlow 组件 | 规则链 `ticketRuleChain` |
| `TicketTypeEnum` / `TicketStatusEnum` / `TicketPriorityEnum` / `TicketRuleTypeEnum` | 枚举 | 工单类型、状态、优先级、规则类型 |

**接口**：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/iot/ticket/list` | 工单分页 |
| GET | `/iot/ticket/records` | 流转记录 |

**规则引擎**：规则链定义在 `resources/liteflow/ticket-rule.el.xml`（`THEN(prepare, load, IF(hasRule, THEN(match, IF(matched, apply, noop)), noop))`）。链路标识 `IotConstants.TICKET_RULE_CHAIN_ID`，命中后由服务层统一持久化并写入流转记录。

**流程引擎**：通过 `WorkflowService`（Warm-Flow，`warm-flow.enabled=true` 时可用）发起与办理流程；`businessId` 取工单 ID，办理后回写 `flowCode/processInstanceId/businessStatus`，状态映射见 `BusinessStatusEnum`。

前端页面：`views/ticket/index.vue`（工单列表 / 规则配置 Tab，含详情与流转时间线、办理/流程办理弹窗）；接口封装 `src/api/ticket.js`；建表脚本 `iot_ticket.sql`。

## 14. job · 任务调度

**职责**：统一的任务定义与执行管理，内置本地调度器，并可对接 SnailJob 分布式调度中心。

| 类 | 类型 | 说明 |
| --- | --- | --- |
| `IotJobInfoController` | 控制器 | 前缀 `/iot/job/info`，任务 CRUD、启停、手动触发、执行器清单 |
| `IotJobLogController` | 控制器 | 前缀 `/iot/job/log`，执行日志查询与清理 |
| `IotJobInfo` / `IotJobLog` | 实体 | 任务定义 / 执行日志（表 `iot_job_info` / `iot_job_log`） |
| `JobTypeEnum` | 枚举 | `LOCAL`（本地）/ `SNAILJOB`（SnailJob） |
| `JobTriggerTypeEnum` | 枚举 | `CRON` / `FIXED_RATE` / `MANUAL` / `SNAILJOB` |
| `JobExecuteStatusEnum` | 枚举 | `SUCCESS` / `FAIL` |
| `JobHandler` | 接口（SPI） | `name()` / `description()` / `execute(params)` |
| `JobHandlerRegistry` | 注册表 | 启动时索引全部 `JobHandler`，按名称查找 |
| `HeartbeatJobHandler` | 实现 | `heartbeatJob`，系统心跳检测 |
| `CleanJobLogHandler` | 实现 | `cleanJobLog`，清理历史日志（参数 `{"days":7}`，默认 7 天） |
| `IotJobInvoker` | 支撑 | 统一调用入口：执行 Handler、落 `iot_job_log`、回写 `lastFireTime` |
| `IotJobScheduler` | 调度器 | 本地 Cron / 固定频率调度（`ThreadPoolTaskScheduler`） |
| `IotJobDispatchExecutor` | SnailJob 适配器 | `@JobExecutor(name = "iotJobDispatch")` |

**接口**：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/iot/job/info/list` | 任务分页 |
| GET | `/iot/job/info/{jobId}` | 任务详情 |
| POST / PUT / DELETE | `/iot/job/info`、`/iot/job/info/{jobId}` | 增改删 |
| PUT | `/iot/job/info/changeStatus/{jobId}/{status}` | 启停 |
| POST | `/iot/job/info/trigger/{jobId}` | 手动触发一次 |
| GET | `/iot/job/info/handlers` | 可用执行器清单 |
| GET | `/iot/job/log/list` | 执行日志分页 |
| DELETE | `/iot/job/log` | 清理日志 |

**触发方式**：`LOCAL + CRON` / `LOCAL + FIXED_RATE` 由 `IotJobScheduler` 本地调度；`SNAILJOB` 类型由 SnailJob 服务端调度并回调 `iotJobDispatch`；手动触发对任意任务生效。

**SnailJob 对接**：客户端由 `iot-common-job` 的 `SnailJobConfig` 激活，需 `snail-job.enabled=true`（dev 默认关闭、prod 开启），执行器组 `ruoyi_group`。

前端页面：`views/job/index.vue`（任务列表 / 执行日志 Tab，含 CRON/固定频率/SnailJob 条件字段表单与日志详情弹窗）；接口封装 `src/api/job.js`；建表脚本 `iot_job.sql`（含菜单权限与种子任务）。
