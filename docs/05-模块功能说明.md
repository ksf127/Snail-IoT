## 3. device · 产品与设备

**职责**：IoT 产品定义、设备实例管理、物模型与分组归属。

| 类 | 类型 | 说明 |
| --- | --- | --- |
| `IotProductController` | 控制器 | 产品 CRUD，前缀 `/iot/product` |
| `IotDeviceController` | 控制器 | 设备 CRUD，前缀 `/iot/device` |
| `IotProduct` / `IotDevice` | 领域实体 | 产品/设备 |
| `IotProductBo` / `IotDeviceBo` | 入参 | 新增/修改 |
| `IotProductVo` / `IotDeviceVo` | 出参 | 查询返回 |
| `IotProductMapper` / `IotDeviceMapper` | Mapper | MyBatis-Plus |

**典型流程**：先建产品（定义协议、物模型）→ 在其下注册设备 → 设备上报数据（见 collect）。

## 5. collect · 数据采集

**职责**：设备数据上行接入、Kafka 投递、Elasticsearch 时序落库。

| 类 | 说明 |
| --- | --- |
| `MqttDeviceDataSubscriber` | 订阅 EMQX 设备主题（mica-mqtt），组装消息 |
| `DeviceDataKafkaProducer` | 将采集消息投递到 Kafka |
| `DeviceDataKafkaConsumer` | 消费 Kafka 消息，写入 ES / 落库 |
| `IotDeviceDataEsMapper` | Easy-ES 时序索引 Mapper |
| `IotDeviceDataDoc` | ES 文档模型 |
| `DeviceDataMessage` | 采集消息载体 |
| `DeviceCollectController` | HTTP 采集入口，前缀 `/iot/collect/https` |

**数据链路**：

```
设备 ──MQTT──▶ EMQX ──▶ MqttDeviceDataSubscriber ──▶ Kafka ──▶ DeviceDataKafkaConsumer
                                                                      ├─▶ Elasticsearch(时序检索)
                                                                      └─▶ PostgreSQL(关系/最新值)
```

> 也可通过 `POST /iot/collect/https` 以 HTTP 方式接入。

## 11. pay · 聚合支付

**职责**：统一下单、支付回调、退款、虚拟商品货架，渠道可插拔。

| 类 | 类型 | 说明 |
| --- | --- | --- |
| `PayController` | 控制器 | 前缀 `/iot/pay`（回调 `/iot/pay/notify/**` 免鉴权） |
| `PayProductController` | 控制器 | 前缀 `/iot/pay/product`，虚拟商品货架 CRUD（权限 `iot:pay:product`） |
| `IotPayService` / `IotPayServiceImpl` | 服务 | 支付业务编排 |
| `IotPayProductService` / `IotPayProductServiceImpl` | 服务 | 商品货架维护 |
| `IPayChannel` | 接口 | 支付渠道抽象 |
| `PayChannelFactory` | 工厂 | 收集全部 `IPayChannel` 实现，按 `channelCode` 路由 |
| `MockPayChannel` | 实现 | 本地模拟渠道（`mock`） |
| `AliQrPayChannel` | 实现 | 支付宝扫码/当面付（`ali_qr`，RSA2 验签） |
| `WxNativePayChannel` | 实现 | 微信 Native 扫码（`wx_native`，APIv3 AES-GCM 回调解密） |
| `IotPayOrder` / `IotPayRefund` / `IotPayChannelConfig` / `IotPayProduct` | 实体 | 订单/退款/渠道配置/虚拟商品 |
| `PayStatusEnum` / `RefundStatusEnum` / `PayChannelEnum` / `PayProductTypeEnum` | 枚举 | 状态、渠道与商品类型 |
| `PrePayResult` / `PayNotifyResult` / `RefundResult` | 模型 | 统一返回 |

**扩展新渠道**：实现 `IPayChannel` 并注册为 Spring Bean 即可，`PayChannelFactory` 构造时自动收集全部渠道实现。

**虚拟商品下单**：`iot_pay_order` 通过 `product_id` 关联 `iot_pay_product`；下单时指定 `productId` 即以商品名称与售价落单（金额由服务端校验，避免客户端篡改），未指定则按自由金额下单。脚本预置一件默认虚拟商品「虚拟服务」（`PRD-VIRTUAL-SERVICE`，￥9.90）。

前端页面：`views/pay/index.vue`（订单/退款/渠道配置/商品管理 Tab）；商品管理子组件 `views/pay/components/ProductManage.vue`；接口封装 `src/api/pay.js`；建表脚本 `iot_pay.sql`。

## 12. ticket · 工单管理

**职责**：工单全生命周期管理，支持三类工单与两种引擎编排：

| 工单类型 | 说明 |
| --- | --- |
| `normal` 普通工单 | 人工流转（受理 → 处理 → 完成/关闭/驳回） |
| `rule` 规则工单 | 提交时触发 **LiteFlow 规则引擎**，按规则命中自动分配/调整优先级/自动关闭 |
| `flow` 流程工单 | 提交时发起 **Warm-Flow 审批流程**，按流程任务办理并回写状态 |

| 类 | 类型 | 说明 |
| --- | --- | --- |
| `IotTicketController` | 控制器 | 前缀 `/iot/ticket`（列表/详情/增删改、提交、跑规则、办理、流程办理/同步） |
| `IotTicketRuleController` | 控制器 | 前缀 `/iot/ticket/rule`，规则配置 CRUD（权限 `iot:ticket:rule:*`） |
| `IotTicketService` / `IotTicketServiceImpl` | 服务 | 工单编排：状态机流转 + 规则引擎 + 流程引擎 |
| `IotTicketRuleService` / `IotTicketRuleServiceImpl` | 服务 | 规则配置维护 |
| `IotTicket` / `IotTicketRecord` / `IotTicketRule` | 实体 | 工单 / 流转记录 / 规则 |
| `TicketRuleContext` + `TicketRule*Component` | LiteFlow 组件 | 规则链 `ticketRuleChain`：准备 → 加载 → 判定 → 匹配 → 应用 |
| `TicketTypeEnum` / `TicketStatusEnum` / `TicketPriorityEnum` / `TicketRuleTypeEnum` | 枚举 | 工单类型、状态、优先级、规则类型 |

**规则引擎**：规则链定义在 `resources/liteflow/ticket-rule.el.xml`（`THEN(prepare, load, IF(hasRule, THEN(match, IF(matched, apply, noop)), noop))`）。链路标识 `IotConstants.TICKET_RULE_CHAIN_ID`，命中后由服务层统一持久化并写入流转记录。

**流程引擎**：通过 `WorkflowService`（Warm-Flow，`warm-flow.enabled=true` 时可用）发起与办理流程；`businessId` 取工单ID，办理后回写 `flowCode/processInstanceId/businessStatus`，状态映射见 `BusinessStatusEnum`。

前端页面：`views/ticket/index.vue`（工单列表 / 规则配置 Tab，含详情与流转时间线、办理/流程办理弹窗）；接口封装 `src/api/ticket.js`；建表脚本 `iot_ticket.sql`。

## 14. job · 任务调度

**职责**：统一的任务定义与执行管理，内置本地调度器，并可对接 SnailJob 分布式调度中心。

| 类 | 类型 | 说明 |
| --- | --- | --- |
| `IotJobInfoController` | 控制器 | 前缀 `/iot/job/info`，任务 CRUD、启停、手动触发、执行器清单（权限 `iot:job:info:*`） |
| `IotJobLogController` | 控制器 | 前缀 `/iot/job/log`，执行日志查询与清理（权限 `iot:job:log:*`） |
| `IotJobInfo` / `IotJobLog` | 实体 | 任务定义 / 执行日志（表 `iot_job_info` / `iot_job_log`） |
| `JobTypeEnum` | 枚举 | `LOCAL`（本地）/ `SNAILJOB`（SnailJob） |
| `JobTriggerTypeEnum` | 枚举 | `CRON` / `FIXED_RATE` / `MANUAL` / `SNAILJOB` |
| `JobExecuteStatusEnum` | 枚举 | `SUCCESS` / `FAIL` |
| `JobHandler` | 接口（SPI） | `name()` / `description()` / `execute(params)`，本地任务执行单元 |
| `JobHandlerRegistry` | 注册表 | 启动时索引全部 `JobHandler`，按名称查找 |
| `HeartbeatJobHandler` | 实现 | `heartbeatJob`，系统心跳检测 |
| `CleanJobLogHandler` | 实现 | `cleanJobLog`，清理历史日志（参数支持 `{"days":7}`，默认 7 天） |
| `IotJobInvoker` | 支撑 | 统一调用入口：按任务ID/实体执行 Handler，落 `iot_job_log`，回写 `lastFireTime`，异常不外抛 |
| `IotJobScheduler` | 调度器 | 本地 Cron / 固定频率调度（`ThreadPoolTaskScheduler`），应用启动时自动注册已启用任务 |
| `IotJobDispatchExecutor` | SnailJob 适配器 | `@JobExecutor(name = "iotJobDispatch")`，将 SnailJob 触发转交 `IotJobInvoker` |
| `IotJobInfoService` / `IotJobLogService`（及 Impl） | 服务 | 任务与日志业务编排 |

**触发方式**：`LOCAL + CRON` / `LOCAL + FIXED_RATE` 由 `IotJobScheduler` 本地调度；`SNAILJOB` 类型由 SnailJob 服务端调度并回调 `iotJobDispatch`；`POST /iot/job/info/trigger/{jobId}` 支持任意任务手动触发一次。

**SnailJob 对接**：客户端由 `iot-common-job` 的 `SnailJobConfig` 激活，需 `snail-job.enabled=true`（dev 默认关闭、prod 开启），执行器组 `DEFAULT_GROUP`。

前端页面：`views/job/index.vue`（任务列表 / 执行日志 Tab，含 CRON/固定频率/SnailJob 条件字段表单与日志详情弹窗）；接口封装 `src/api/job.js`；建表脚本 `iot_job.sql`（含菜单权限与种子任务）。
